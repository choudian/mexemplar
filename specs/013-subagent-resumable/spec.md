# Feature Specification: 子代理可唤回机制（Resumable / Re-dispatchable Subagent）

**Feature Branch**: `013-subagent-resumable`
**Created**: 2026-06-02
**Status**: Draft
**Input**: User description: "这次做上边的这个计划" —— 指代已敲定的设计计划：临时子代理在被迫中断（迭代超限 / LLM 调用最终失败）时不再丢弃已完成工作，而是转为可暂停、可唤回的状态；主代理可查看子代理工作概览并决定续跑还是新开。

## User Scenarios & Testing *(mandatory)*

本特性的主要 actor 是**主代理（办公助理 Assistant）**——一个自主决策的 ReAct agent；次要 actor 是**最终用户**（在账单/网络类失败场景中需要被告知与恢复）。

### User Story 1 - 迭代超限后唤回续跑 (Priority: P1)

主代理把一个复杂任务委派给临时子代理；子代理因任务本身复杂、在达到迭代上限时仍未完成。系统不丢弃它的工作，而是把它转为"暂停"，并把可唤回的标识符返回给主代理。主代理判断任务确实在正常推进后，唤回该子代理，让它带着已有工作历史接着干，直到完成。

**Why this priority**: 这是特性的核心价值——避免"干了很久、撞上限、全部白干、从零重派"的浪费。单独实现它即构成可用的 MVP。

**Independent Test**: 委派一个会触发迭代上限的任务 → 确认返回"暂停 + 子代理标识符"而非失败 → 唤回 → 确认子代理从断点继续并最终产出结果。全程已完成工作零丢失。

**Acceptance Scenarios**:

1. **Given** 一个委派出去、跑到迭代上限仍未完成的子代理，**When** 子代理停止，**Then** 委派结果标记为"暂停（可唤回）"、附暂停原因"迭代超限"和一个子代理标识符，且子代理工作历史完整保留。
2. **Given** 一个处于暂停态的子代理标识符，**When** 主代理唤回它，**Then** 子代理从上次断点继续执行（无需主代理重述原始任务），完成后返回最终结果。
3. **Given** 唤回后子代理再次达到（新的）迭代上限，**When** 它再次停止，**Then** 仍返回"暂停（可唤回）"，主代理可再次唤回（可重复）。

---

### User Story 2 - 调用失败后保活、待恢复再续 (Priority: P1)

主代理委派的子代理在执行中遭遇 LLM 服务方失败——**账户级配额/账单超限**（套餐用尽、余额不足）或**网络持续中断**。这类失败重试无用、当下立即唤回也会立即再失败。系统把子代理工作原地冻结、完整保活；主代理识别出这是"需等外部恢复"的失败，告知用户原因，待配额/网络恢复后（即使期间进程重启过）再唤回子代理接着干。

**Why this priority**: 账单/网络失败是真实高频场景，且其工作丢失代价最痛（往往已跑了很多步）。保活 + 跨重启可唤回是与 US1 并列的核心价值。

**Independent Test**: 制造一次持续的 LLM 调用失败（如临时置入无效凭据 / 断网）→ 确认子代理转为"暂停"、原因标明为调用失败类、工作历史保留 → 恢复条件后唤回 → 确认成功继续。

**Acceptance Scenarios**:

1. **Given** 一个子代理在执行中 LLM 调用经重试仍最终失败，**When** 它停止，**Then** 返回"暂停（可唤回）"、暂停原因标明为"调用失败（账单或网络）"，工作历史完整保留。
2. **Given** 一个因调用失败而暂停的子代理，**When** 外部条件恢复后主代理唤回它，**Then** 子代理成功从断点继续。
3. **Given** 因调用失败而暂停的子代理、且其间应用进程已重启，**When** 主代理用之前的子代理标识符唤回，**Then** 仍能基于持久化的工作历史成功恢复（不依赖进程内存）。

---

### User Story 3 - 诊断"任务复杂"还是"走弯路" (Priority: P2)

迭代超限隐含"干了很久没干完"，根因可能是任务确实复杂（应续跑），也可能是模型在原地打转/走错方向（盲目续跑只会越陷越深，应新开）。主代理在唤回前可调取子代理的**工作概览**——迭代轮数、调用过哪些工具及次数、最后一次产出、当前状态——据此自主判断该续跑还是放弃旧的、重新委派一个新子代理。

**Why this priority**: 提升唤回决策质量，避免对"走弯路"的子代理无效续跑。依赖 US1 已存在的暂停态，是其上的增强。

**Independent Test**: 对一个暂停子代理请求工作概览 → 确认返回轮数/工具调用统计/最后产出/状态，且**不触发任何额外的模型调用** → 主代理据此分别走"续跑"或"重新委派"两条路。

**Acceptance Scenarios**:

1. **Given** 一个暂停或已结束的子代理，**When** 主代理请求其工作概览，**Then** 返回结构化概览（轮数、各工具调用次数、最后产出、状态），且过程不消耗额外模型调用。
2. **Given** 概览显示子代理在少数几个工具间反复打转、无实质进展，**When** 主代理判断为"走弯路"，**Then** 主代理可重新委派一个新子代理（并能在新委派中说明要避开的弯路），而非续跑旧的。

---

### User Story 4 - 对已完成但未达标的结果返工 (Priority: P3)

子代理正常完成并返回结果，但主代理审查后判断没达标（如"只整理了 50 项中的 30 项"）。主代理无需从零重新委派，可用追加指令唤回同一个子代理（它仍带着已完成的上下文），让它补齐/修正。

**Why this priority**: 锦上添花的复用能力。把"唤回"范围从"被迫中断"扩展到"任何属于自己的子代理"，减少重复铺垫上下文。优先级最低，因可被"重新委派"替代，只是效率更低。

**Independent Test**: 让子代理正常完成一个部分达标的任务 → 主代理带追加指令唤回 → 确认子代理在原有上下文基础上补齐，而非重头再来。

**Acceptance Scenarios**:

1. **Given** 一个已正常完成的子代理，**When** 主代理带追加指令唤回它，**Then** 该指令作为新输入进入子代理的已有上下文，子代理在此基础上继续，不丢弃此前成果。

---

### Edge Cases

- **重复唤回**：续跑后再次中断（超限或失败）→ 仍可被再次唤回，次数不设硬上限（由主代理判断停止）。
- **唤回不存在/非己出的子代理**：标识符无效，或指向并非"当前主代理派出"的会话 → 系统拒绝唤回/查看，返回明确错误，绝不泄露他人会话内容。
- **续跑时上下文过长**：子代理历史很长导致单次上下文偏大 → 由既有的上下文管理（按需压缩）处理；注意账单类失败属于配额问题，压缩不能解决，需等外部恢复。
- **唤回一个仍在运行的子代理**：标识符指向尚未停止的会话 → 拒绝并发唤回，提示当前不可恢复。
- **空产出的暂停**：子代理几乎没产出就暂停（如第 1 轮即调用失败）→ 概览如实反映（轮数极少、无有效产出），主代理据此多半选择重新委派。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 临时子代理达到迭代上限而未完成时，系统 MUST 将其转为"暂停（可唤回）"状态并完整保留其工作历史，而非作为失败丢弃。
- **FR-002**: 临时子代理的模型调用经既有重试后仍最终失败（账户配额/账单超限、网络持续中断等）时，系统 MUST 将其转为"暂停（可唤回）"状态并保留工作历史，而非作为错误丢弃。
- **FR-003**: 暂停结果 MUST 携带可区分的**暂停原因**，至少区分"迭代超限"与"调用失败（账单/网络）"两类，使主代理能采取不同策略。
- **FR-004**: 委派与暂停结果 MUST 返回一个**子代理标识符**，供后续查看与唤回使用。
- **FR-005**: 主代理 MUST 能获取指定子代理的**工作概览**：迭代轮数、调用过的工具及次数、最后一次产出、当前状态；该操作 MUST NOT 触发额外的模型调用。
- **FR-006**: 主代理 MUST 能**唤回**任意属于自己的子代理继续执行，包括因中断而暂停的、以及已正常完成的；唤回时 MUST 允许附加可选的追加指令。
- **FR-007**: 唤回 MUST 基于**持久化的工作历史**恢复，不依赖应用进程内存；即使期间进程重启，凭子代理标识符仍可唤回。
- **FR-008**: 唤回与查看 MUST 校验子代理**归属**，拒绝针对"非当前主代理派出的会话"的访问，且不得泄露其内容。
- **FR-009**: 被唤回的子代理若再次中断（超限或调用失败）MUST 仍可被再次唤回（支持重复唤回）。
- **FR-010**: 系统 MUST 在主代理的决策层提供明确**引导**，使这个自主决策的 ReAct 主代理知道：暂停后先查看概览诊断、任务复杂则续跑、走弯路则新开、账单/网络类失败需等恢复、已完成但未达标可带指令返工。
- **FR-011**: 对**非临时子代理**的其它 agent，迭代超限与调用失败的既有处理行为 MUST 保持不变（无回归）。

### Key Entities

- **子代理工作会话（Subagent Work Session）**：一次委派对应的、持久化的子代理对话历史。关键属性：子代理标识符、归属主代理、当前状态（运行中/暂停/已完成）、可用工具范围。是唤回与查看的数据来源。
- **暂停原因（Pause Reason）**：描述子代理为何暂停，至少区分"迭代超限"与"调用失败（账单/网络）"，驱动主代理的不同后续策略。
- **工作概览（Work Overview）**：对子代理工作会话的机械式只读摘要——迭代轮数、各工具调用次数、最后产出、状态；不含模型再加工。

### Constraints & Compatibility

- **CC-001**: 子代理工作历史 MUST 依赖持久化会话存储而非进程内存，以保证跨进程重启的可唤回性（支撑账单超限等长时间等待场景）。
- **CC-002**: "100% 调度"约束不变——主代理本体不直接执行任务，唤回的仍是子代理；本特性不引入主代理直接执行的路径。
- **CC-003**: 已沉淀/会话数据"不物理删除"的原则不受影响——唤回是基于既有历史的恢复，不删除、不改写历史条目。
- **CC-004**: 默认 agent 的中断处理不得回归（见 FR-011）。

- [ ] **Recording** (`src/recording/`)
- [ ] **Utils** (`src/utils/`)

### Agent Impact

- **受影响 Agent**：Assistant（主代理）、Ephemeral Subagent（临时子代理）。
- **新增/修改工具**：新增 `inspect_subagent`（查看工作概览，零模型调用）、`continue_subagent`（唤回续跑，可带追加指令）；修改 `delegate_to_subagent`（返回携带子代理标识符，暂停时附暂停原因）。
- **System prompt 改动**：Assistant system prompt 新增"子代理暂停处理"引导段（对应 FR-010）。
- **Orchestrator dispatch 改动**：新增唤回与查看的编排路径、子代理归属校验；临时子代理配置标记为"可唤回失败"（迭代超限/调用失败转暂停）。

### Data Store Impact

- **SQLite** (`src/data/repos/`)：复用既有 session / message 持久化；预期**不新增表、不新增迁移**。唤回基于按会话标识符读取的持久化历史。
- **DuckDB**：无影响。
- **Config** (`src/data/unified_config.py`)：无新增对外配置键（迭代上限等沿用既有内部配置）。
- **Secrets** (keyring)：无影响。

### Event Impact

- 可能新增一条**内部 workflow transition**（如"委派已暂停"）用于编排可追溯性；属后端编排内部记录，非面向前端的公开 UI 事件。
- 本期**不**新增 UI Event Registry 公开事件（不在 UI 展示暂停子代理；如未来需要再单独注册）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 子代理被迫中断后，其已完成工作 100% 保留并可唤回继续——零工作丢失。
- **SC-002**: 主代理唤回一个暂停子代理时，无需重述原始任务即可让其从断点继续（恢复不要求重新铺垫上下文）。
- **SC-003**: 因账单/网络失败而暂停的子代理，在外部条件恢复后（含应用进程已重启的情况）仍可被成功唤回。
- **SC-004**: 主代理可在**不消耗任何额外模型调用**的前提下获取子代理工作概览。
- **SC-005**: 同一子代理支持被多次重复唤回（续跑→再暂停→再续跑）直至完成。
- **SC-006**: 对非临时子代理的其它 agent，迭代超限与调用失败的处理行为零变化（既有相关测试全部通过）。
- **SC-007**: 针对非本主代理派出的会话标识符的查看/唤回请求，100% 被拒绝且不泄露其内容。

## Assumptions

- 子代理的对话历史已由现有会话存储持久化（现状如此），因此唤回无需引入新的序列化/持久化机制。
- 主代理是自主决策的 ReAct agent，其"何时查看/续跑/新开"的行为依赖工具描述与 system prompt 引导共同塑造（而非系统写死的阈值规则）。
- 唤回时子代理使用主代理**当前**可用的工具范围（不强制还原原始委派时的工具白名单子集），因为当前可用范围对续跑同样合理。
- "调用失败可唤回"覆盖的是**账户配额/账单超限与网络持续中断**这类需等外部恢复的失败；**输出长度截断**不属于失败、不触发暂停。
- 当前为单用户、未发布阶段，无外部脚本/API 消费者，无需为本特性预留对外兼容或双发路径。
