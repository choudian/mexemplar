**Severity**: Critical
**Feature**: `032-delegation-context-handoff`
**Reported**: 2026-07-17
**Status**: Patched
**Patched**: 2026-07-17

## Description

`$speckit-review-run all` 的 T019 在 032 分支内保留了非平凡的 MCP server 生命周期竞争修复和 Desktop API lifespan shutdown facade 接线，但 032 的 `spec.md` 仍声明 Desktop API 不涉及，`plan.md` 仍声明改动只集中在委派 business/data seam。`tasks.md` 虽然事后记录了实现和测试，却不能替代 implementation plan 对实际受影响层、约束、结构、测试与活文档的声明。

该差异触发 Constitution 的计划完整性门禁：每份实现计划 MUST 标明受影响的层、事件、数据存储、配置/密钥、测试与文档更新点。

## Artifact Traceability

### spec.md

- **Affected user story**: 三个委派 user story 本身不变；缺口属于综合审查产生的相邻可靠性修复。
- **Affected requirements**: FR-010 的“0 新公开 UI 事件/secret/schema”仍成立，但缺少 MCP startup attempt 与 shutdown 的确定性要求。
- **Affected sections**: Edge Cases、Functional Requirements、Constraints & Compatibility、Architecture Impact、Success Criteria、Assumptions。
- **Gap identified**: 未声明 `src/business/mcp/` 与 `src/desktop_api/app.py` 的实际影响，也没有迟到成功隔离、有界 shutdown 和 service facade 的验收条件。

### plan.md

- **Affected sections**: Summary、Technical Context、Constitution Check、Project Structure、核心设计决策、Regression Compatibility Note、Complexity Tracking。
- **Impact**: 原计划的“仅动 business/data”“0 desktop_api 改动”与分支 diff 冲突，且未列出 MCP/desktop API 测试与 027 lifecycle contract。

### tasks.md

- **Affected tasks**: T019 已实现并测试 MCP lifecycle 修复；新增 T020 负责补齐规格影响面并重新验证。
- **False completions**: 无。T019 的代码交付真实存在，不应重开。
- **Missing tasks**: 缺少跨工件一致性修复任务。

## Root Cause Analysis

综合代码审查在委派 feature 的收尾阶段同时发现了既有 MCP 生命周期竞争。实现、测试、027 contract 和 Architecture 文档被直接修补，T019 也记录了结果，但 032 的 source-of-truth spec/plan 没有随实际分支范围同步，形成“代码与局部文档正确、feature plan 错报影响面”的规格缺口。

## Applied Fix

1. 在 032 `spec.md` 中增加相邻 MCP 生命周期修复场景、FR-011/FR-012、CC-005/CC-006、Desktop API 影响和 SC-006/SC-007。
2. 在 032 `plan.md` 中补齐 MCP/Desktop API 技术上下文、Constitution Check、源码/测试结构、设计决策和复杂度记录，并引用 027 lifecycle contract 作为权威协议。
3. 在 `tasks.md` 增加 T020，跟踪跨工件一致性及验证门禁。
4. 运行 `/speckit.bugfix.verify` 与 `$speckit-verify-run all` 确认缺口关闭。
