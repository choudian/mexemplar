# Bug Report: MCP SDK 清理失败被伪装成功且计划文件清单不完整

**Type**: Implementation defect + Spec gap
**Severity**: Critical（VERIFY-F1）/ Low（VERIFY-G1）
**Feature**: `032-delegation-context-handoff`
**Reported**: 2026-07-18
**Status**: Patched
**Patched**: 2026-07-18
**Source Findings**: `VERIFY-F1`, `VERIFY-G1`

## Description

`McpProcessManager._stop_server_coro()` 在 running server 的 `AsyncExitStack.aclose()` 超时或抛异常时只记录 warning，随后清空缓存并正常返回。公开 `stop_server()`、`stop_all()` 与 `shutdown()` 因而可能报告成功，但 SDK 管理的子进程资源并未确认完成释放，形成静默失败和 orphan-process risk。

同一轮验证还发现 032 `plan.md` 的 Project Structure 未完整列出分支实际修改文件，遗漏 `src/business/agents/builtin_tools.py`、`src/business/orchestration/agent/tool_registry.py`、统一配置与 dispatch 回归测试等影响面。

## Root Cause Analysis

T019 把 startup task、drain、join 等失败纳入 shutdown 汇总，却保留了 `_stop_server_coro()` 对 `stack.aclose()` 的旧 warning-only 分支。缓存清理和外部资源释放被错误地当成同一个成功结果，导致本地状态虽收口，调用方却无法获知 SDK cleanup 失败。

计划清单则在 BUG-001 修复时只补了 MCP/Desktop API 主要文件，没有用完整 branch diff 反查委派主线的辅助 facade、配置契约测试和集成回归文件，留下低严重度的追踪缺口。

## Applied Fix

1. 先增加公开 stop 的 stack close 异常/超时测试和同步 shutdown 传播测试，确认修复前出现假成功。
2. `_stop_server_coro()` 改为汇总 startup 与 SDK stack cleanup 错误；无论 cleanup 成败都清空本地缓存，随后抛出单一或聚合失败，由 `stop_all()` / `shutdown()` 继续传播。
3. 同步 032 spec/plan、027 lifecycle contract 与 `docs/ARCHITECTURE.md`；删除未实现 `_terminate_tree` PID fallback 的错误承诺。
4. 用完整 branch diff 补齐 plan Project Structure，并通过 T023 跟踪定向回归、门卫和跨工件验证。
