# Data Model: Frontend Event Layer

## Domain Event

Internal backend fact or request emitted through `src/utils/events.py`.

- `name`: backend-only blinker signal name.
- `payload`: backend payload from the sending component.
- Visibility rule: never exposed directly to React and never used by React state handlers.

## UI Event Registry Entry

Backend-owned public contract row for one frontend event type.

- `event_type`: stable public event type, for example `teaching.stage_changed`.
- `category`: `notification`, `interactive`, or `control`.
- `payload_keys`: allowlisted keys accepted for payload emission.
- `example`: safe example payload used by contract tests.
- `scope_keys`: supported scope identifiers such as `workflowId`, `sessionId`, `toolId`, or `compositionId`.
- `frontend_domains`: frontend stores expected to handle the event.

Validation rules:

- Every emitted event type must exist in the registry.
- Payloads must include only allowlisted keys.
- Example payloads must pass the same safety validator used at publish time.

## UI Event Envelope

Public event wrapper delivered through `/api/events`.

- `eventId`: unique event identifier.
- `sequence`: integer unique and monotonic within the current desktop session.
- `sessionId`: backend-generated event-session identifier; changes after process restart.
- `causationId`: optional identifier tying a group of UI events to one backend cause.
- `type`: registered UI event type.
- `scope`: frontend routing scope.
- `payload`: allowlisted public payload.
- `createdAt`: UTC timestamp.

Validation rules:

- `sequence` must increase for every published UI event.
- `sessionId` must match the current event hub session.
- `payload` must never contain runtime tokens, secrets, full code, full command bodies, raw stack traces, database paths, raw query results, or unfiltered recording data.

## Subscriber

One frontend event-stream connection.

- `subscriber_id`: generated by the hub.
- `queue`: bounded per-subscriber queue.
- `last_seen_sequence`: sequence received from the frontend on reconnect.
- `scope`: optional subscription scope for interactive requests.
- `status`: active, overflowed, or closed.

Lifecycle:

1. Subscriber connects with optional `Last-Event-ID` or `lastSeenSequence`.
2. Hub replays buffered same-session events if the buffer fully covers the gap.
3. Hub emits `backend.resync_required` and closes if replay cannot cover the gap.
4. On overflow, only the slow subscriber receives resync/close; other subscribers continue.

## Interactive Request

Pending user decision for trial preview confirmation.

- `requestId`: stable decision identifier.
- `workflowId`: workflow scope.
- `trialId`: trial execution identifier.
- `summary`: user-safe preview/risk summary.
- `codePreview`: truncated/sanitized preview, never full code.
- `riskSummary`: user-safe risk text.
- `expires_at`: backend-generated deadline.
- `decision`: pending, approve, deny, timeout, disconnect, overflow, or shutdown.

Validation rules:

- Only the first valid decision before `expires_at` can change the result.
- All non-approve terminal outcomes are treated as denial by the waiting backend workflow.
- Duplicate or conflicting decisions report already-resolved/conflict without changing the stored outcome.
