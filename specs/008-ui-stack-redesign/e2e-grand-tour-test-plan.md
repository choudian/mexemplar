# Grand Tour 全栈 E2E 自动化测试计划

**版本**: 1.0
**创建日期**: 2026-05-14
**测试类型**: 全栈端到端（前端 + 真实 Python 后端 + 数据库）
**测试框架**: Playwright + Python sidecar
**状态**: 待验证

---

## 1. 测试范围

### 1.1 测试目标

验证一个真实用户能在 Mexemplar 桌面应用中完成以下业务目标：

1. 启动应用并确认系统就绪
2. 浏览已有技能（已掌握、待考核、失败记录）
3. 创建技能组合并发布
4. 在 AI 助手中发起对话
5. 调整应用设置和密钥
6. 教系统一个新技能
7. 在屏幕间自由切换而不丢失数据

### 1.2 与现有测试的区别

| 维度 | 现有 E2E 测试 | Grand Tour |
|------|-------------|------------|
| 后端 | mock API（`page.route()` 拦截） | 真实 Python sidecar |
| 数据库 | 无 | 真实 SQLite |
| 断言视角 | API 调用是否正确接线 | 用户能不能完成任务 |
| 测试组织 | 每个屏幕独立 | 一条连贯的用户旅程 |
| 验证重点 | 接口通了没有 | 页面反馈是否符合用户预期 |

### 1.3 排除范围

- AI 模型回复的准确性（依赖 LLM，不在自动化测试范围内）
- 教学流程的完整闭环（意图分析、学习、试用——需要 LLM 参与）
- 桌面录制模式（需要真实桌面环境）
- 性能和压力测试

---

## 2. 测试环境

### 2.1 环境启动

Playwright `globalSetup` 自动完成以下步骤：

1. 创建临时数据目录（测试结束后删除）
2. 启动 Python sidecar（`uv run python -m src.desktop_api --port 18900 --token e2e-test-token`）
3. 轮询健康检查等待就绪
4. 运行种子数据脚本填充初始数据
5. 启动 Vite dev server，环境变量指向真实 sidecar

### 2.2 种子数据

| 数据 | 内容 | 用途 |
|------|------|------|
| 助手会话 | "Grand Tour 对话" + 2 条历史消息 | TC-GT-004 验证会话历史 |
| 已发布技能 | "邮件分类"（3/3 试用通过） | TC-GT-002/003 浏览和组合 |
| 已发布技能 | "报告生成"（3/3 试用通过） | TC-GT-003 组合成员 |
| 待考核技能 | "数据清洗"（0/3 试用） | TC-GT-002 浏览待考核 |
| 失败记录 | "旧版导入"（trial 阶段超时） | TC-GT-002 浏览失败记录 |
| AI 配置 | 请求超时 120s，模型默认值 | TC-GT-005 修改和保存 |

### 2.3 运行命令

```powershell
cd frontend
npm run test:e2e -- --grep "Grand Tour"
```

## 3. 测试场景

---

### TC-GT-001 用户启动应用确认就绪

**用户目标**：打开应用，确认一切正常可以开始使用。

**前置条件**：sidecar 和前端均已启动。

**测试步骤**：

1. 打开浏览器访问应用首页
2. 等待页面加载完成

**预期结果**：

- ✅ 后端状态指示器显示"已就绪"
- ✅ 左侧导航栏显示五个入口：AI 助手、技能教学、技能列表、技能组合、应用设置
- ✅ 默认显示 AI 助手页面，左侧有会话历史面板

**验证要点**：应用在合理时间内（30 秒）完成启动并显示就绪状态。

---

### TC-GT-002 用户浏览已有技能

**用户目标**：查看系统中已有的技能，了解每个技能的状态。

**前置条件**：数据库中有种子数据（3 个技能 + 1 条失败记录）。

**测试步骤**：

1. 点击左侧"技能列表"进入技能管理页
2. 在默认的"待考核"分类下查看技能
3. 点击"已掌握"分类标签切换
4. 查看"邮件分类"和"报告生成"两个已发布技能
5. 点击"失败记录"分类标签切换
6. 查看"旧版导入"失败记录
7. 回到"已掌握"分类，点击第一个技能的"试用"按钮

**预期结果**：

- ✅ 默认显示"待考核"分类，能看到"数据清洗"技能，显示试用进度 0/3
- ✅ 切换到"已掌握"后，能看到"邮件分类"和"报告生成"，显示为卡片样式
- ✅ 切换到"失败记录"后，能看到"旧版导入"，显示失败原因"执行超时"
- ✅ 点击试用后操作执行，页面不报错不崩溃

**验证要点**：三个分类标签切换流畅，每个分类显示正确状态的技能，操作按钮响应正常。

---

### TC-GT-003 用户创建技能组合

**用户目标**：把"邮件分类"和"报告生成"两个技能组合成一个顺序执行的工作流。

**前置条件**：数据库中有"邮件分类"和"报告生成"两个已发布技能。

**测试步骤**：

1. 点击左侧"技能组合"进入组合管理页
2. 看到当前没有组合，点击"新建组合"
3. 在名称输入框填写"邮件处理工作流"
4. 在描述输入框填写"自动处理客户邮件并生成摘要报告"
5. 在模式下拉框选择"顺序型"
6. 在右侧"已发布技能"面板中点击"邮件分类"添加为第一个成员
7. 点击"报告生成"添加为第二个成员
8. 看到"AI 推荐顺序"按钮出现
9. 在"适用场景"输入框填写使用场景描述
10. 点击"保存草稿"
11. 点击"发布"

**预期结果**：

- ✅ 新建后进入组合编辑器，包含模式选择、成员列表、基础信息表单
- ✅ 添加两个成员后，成员列表按顺序显示
- ✅ 顺序模式下，成员有上移/下移按钮，且出现"AI 推荐顺序"
- ✅ 保存草稿后，底部状态栏更新为"当前：邮件处理工作流"
- ✅ 发布后操作成功完成

**验证要点**：组合创建流程从新建到发布完整可用，所有输入控件响应正常。

---

### TC-GT-004 用户使用 AI 助手

**用户目标**：查看历史对话并发送一条新消息。

**前置条件**：数据库中有种子助手会话和历史消息。

**测试步骤**：

1. 点击左侧"AI 助手"进入对话页面
2. 在会话历史中看到"Grand Tour 对话"
3. 点击选中该会话
4. 查看历史消息
5. 在底部输入框输入"请帮我用邮件处理工作流处理今天的邮件"
6. 点击"发送"

**预期结果**：

- ✅ 会话历史正常显示，能看到"Grand Tour 对话"
- ✅ 点击后进入对话详情，能看到历史消息（助手问候 + 用户请求）
- ✅ 发送消息后输入框清空
- ✅ 新消息显示在对话时间线中

**验证要点**：对话历史加载正确，消息发送功能正常，页面不崩溃。

---

### TC-GT-005 用户调整应用设置

**用户目标**：修改 AI 配置和保存 API 密钥。

**前置条件**：设置页面可正常加载。

**测试步骤**：

1. 点击左侧"应用设置"进入设置页面
2. 将"请求超时"值改为 60
3. 点击"保存设置"
4. 在 API Key 输入框输入测试密钥
5. 点击"保存密钥"

**预期结果**：

- ✅ 设置页面正常加载，显示 AI 配置项
- ✅ 修改超时值后，底部出现"1 项待保存"提示
- ✅ 点击保存后，提示变为"无未保存更改"
- ✅ 保存密钥后，显示"已保存"状态
- ✅ **原始密钥文本不出现在页面任何位置**

**验证要点**：设置修改流程完整可用，密钥安全性得到保障（不明文显示）。

---

### TC-GT-006 用户尝试教学新技能

**用户目标**：开始录制一个浏览器操作流程，教系统新技能。

**前置条件**：教学页面可正常加载，浏览器录制模式就绪。

**测试步骤**：

1. 点击左侧"技能教学"进入教学页面
2. 看到浏览器录制选项（标记为推荐）
3. 点击"开始"按钮创建教学任务
4. 点击"开始录制"
5. 等待录制状态显示
6. 点击"停止录制"
7. 在意图理解阶段看到"需求分析师"界面
8. 在对话框输入"我想录制一个自动处理邮件的流程"
9. 点击发送

**预期结果**：

- ✅ 教学页面显示四步流程指示器
- ✅ 浏览器录制模式标记为"推荐"
- ✅ 点击开始后进入录制阶段，"开始录制"按钮可用
- ✅ 录制中显示"录制中"状态
- ✅ 停止录制后，进入意图理解阶段，显示需求分析师对话界面
- ✅ 发送意图描述后，消息出现在对话中

**验证要点**：教学流程的前半段（模式选择 → 录制 → 意图描述）完整可用。

---

### TC-GT-007 跨屏切换验证

**用户目标**：在不同页面间自由切换，确认之前操作的数据不丢失。

**前置条件**：之前步骤已完成各种操作。

**测试步骤**：

1. 切换到"AI 助手" → 确认"Grand Tour 对话"仍在
2. 切换到"技能列表" → 切换到"已掌握" → 确认"邮件分类"仍在
3. 切换到"技能组合" → 确认页面正常
4. 切换到"应用设置" → 确认"已保存"状态仍在
5. 切换回"AI 助手"

**预期结果**：

- ✅ 每次切换后页面正确加载对应内容
- ✅ 之前操作过的数据（会话、技能、密钥状态）仍然可见
- ✅ 无空白页、无错误提示、无崩溃

**验证要点**：页面导航不会丢失已有数据。

---

## 4. 验收标准

### 4.1 功能验收

- ✅ 全部 7 个场景通过
- ✅ 每个场景的预期结果全部满足
- ✅ 无页面崩溃或 JavaScript 错误

### 4.2 基础设施验收

- ✅ global-setup 能自动启动 sidecar 并就绪
- ✅ 种子数据正确写入数据库
- ✅ global-teardown 正确清理进程和临时文件

### 4.3 已知限制

- AI 对话回复依赖 LLM API Key，无 Key 环境下只验证消息发送成功，不验证 AI 回复内容
- 教学意图分析依赖 LLM，只验证界面交互，不验证 PM Agent 分析结果
- 桌面录制模式不在测试范围内
