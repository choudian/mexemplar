# Bug Report: Intent Reply Auto-Advances Teaching Stage

**Type**: Implementation drift
**Severity**: High
**Feature**: 008-ui-stack-redesign
**Reported**: 2026-05-19

## Description

用户在技能教学的需求确认过程中只回复一句补充说明后，界面直接跳到下一个“技能学习”节点。普通回复不应被当作已确认；只有 PM Agent 提交已确认需求，或用户触发明确确认动作后，流程才应离开 `intent_confirmation`。

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 - Teach A Skill In The Redesigned Flow
- **Affected requirements**: FR-010, FR-023
- **Gap identified**: US3 的 Independent Test 要求“UI advances only when the expected user or system result is available”。当前实现把任意 `/intent/reply` 后的 `intent_confirmation` 响应又自动转成 `/intent/confirm`，使普通回复绕过确认语义。

### plan.md

- **Affected sections**: Phase 1 Design Summary; Project Structure for `frontend/src/state` and `src/desktop_api`
- **Impact**: UI state machine must preserve backend Agent semantics instead of manufacturing a stage transition from the reply response.

### tasks.md

- **Affected tasks**: T057, T059, T066, T070
- **False completions**: Existing T059 coverage allowed reply-to-confirm auto-advance and missed the conversational clarification path.
- **Missing tasks**: Add regression coverage that `/intent/reply` stays in `intent_confirmation` and that the frontend does not call `/intent/confirm` after ordinary replies.

## Root Cause Analysis

`frontend/src/state/teachingStore.ts` called `confirmTeachingIntent()` immediately after `replyTeachingIntent()` whenever the reply response remained in `intent_confirmation`. That made all non-empty user replies behave like explicit confirmation, regardless of whether the user was clarifying, correcting, or only answering one question.

## Recommended Fix

1. Keep `replyIntent()` scoped to `/intent/reply`; do not auto-call `/intent/confirm`.
2. Let the stage move to `learning` only from backend `requirement_confirmed` / `teaching.stage_changed` events or an explicit confirmation action.
3. Add frontend and backend regression tests for the reply-without-advance contract.
