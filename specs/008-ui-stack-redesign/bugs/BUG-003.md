# Bug Report: Raw Trial Failure Message Reaches User UI

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 008-ui-stack-redesign
**Reported**: 2026-05-19

## Description

试用失败时，前端会收到并展示默认英文错误 `Trial failed.`。这个事件是内部编排信号，用于触发 PM 分诊和后续修复，不应该作为用户可见聊天内容或进度消息暴露。

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 - Teach A Skill In The Redesigned Flow
- **Affected requirements**: FR-010, FR-023
- **Gap identified**: US3 要求用户理解教学、学习、试用状态，但不要求暴露内部事件名或默认英文失败占位。试用失败应驱动流程状态和分诊，而不是把 `Trial failed.` 发给用户。

### plan.md

- **Affected sections**: Project Structure for `src/desktop_api/events.py` / `src/desktop_api/ui_events.py`; Phase 1 Design Summary
- **Impact**: Desktop API event projection must translate internal orchestration events into user-facing DTOs and suppress raw internal failure messages.

### tasks.md

- **Affected tasks**: T058, T064, T066, T072
- **False completions**: Existing event-layer coverage validated successful trial projections but did not cover failed trial projection safety.
- **Missing tasks**: Add a regression test that `trial_failed` does not project a user-visible `trial.progress` error message containing `Trial failed.`

## Root Cause Analysis

`src/desktop_api/ui_events.py` projected internal `trial_failed` into a `trial.progress` event with `status: "failed"` and default `error: "Trial failed."`. `frontend/src/state/teachingStore.ts` treats non-running `trial.progress` events as user-visible trial assistant messages, so the internal default surfaced in the UI.

## Recommended Fix

1. Stop projecting internal `trial_failed` as user-visible `trial.progress`.
2. Preserve only the semantic teaching state transition to `failed` with `failureStage: "trial"`.
3. Add event-layer regression coverage that no raw `Trial failed.` payload is published.
