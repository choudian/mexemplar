# Bug Report: Trial Assistant Reply Duplicated And Truncated

**Type**: Implementation drift
**Severity**: High
**Feature**: 008-ui-stack-redesign
**Reported**: 2026-05-19

## Description

后端日志中的试用助手回复包含完整搜索结果预览和“是否符合预期”的追问，但前端页面只显示重复的前半段内容，末尾追问不可见。用户看到的内容与后端实际回复不一致。

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 - Teach A Skill In The Redesigned Flow
- **Affected requirements**: FR-010, FR-023
- **Gap identified**: 试用阶段必须展示真实 Agent 进度和结果；当前 UI 把同一条 trial 回复拆成 headline/detail 两份重复渲染，导致长回复被重复内容挤占，可见内容与后端回复不一致。

### plan.md

- **Affected sections**: Project Structure for `src/desktop_api/ui_events.py` and `frontend/src/state`
- **Impact**: Event DTO fields must avoid carrying the same long body twice, and frontend state mapping must guard against duplicate headline/detail payloads.

### tasks.md

- **Affected tasks**: T058, T064, T066, T072
- **False completions**: Existing trial event tests checked routing but did not verify that long trial assistant replies render once and preserve the full user-facing body.
- **Missing tasks**: Add backend and frontend regressions for trial waiting-for-user replies so duplicated payload fields do not duplicate visible messages.

## Root Cause Analysis

`agent_needs_user_input` for trial agents was projected as `trial.progress` with both `headline` and `message` set to the full LLM response. `frontend/src/state/teachingStore.ts` then stored `headline` as the main text and `message` as detail, causing `TrialStage` to render the same long Markdown body twice.

## Recommended Fix

1. Project trial waiting-for-user replies with a single `headline` body instead of duplicating it into `message`.
2. Defensively suppress `detail` when it equals `headline`.
3. Add tests covering both the backend event payload shape and frontend duplicate-detail guard.
