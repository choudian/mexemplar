# Bug Report: Long Trial Reply Is Visually Clipped

**Type**: Implementation drift
**Severity**: High
**Feature**: 008-ui-stack-redesign
**Reported**: 2026-05-19

## Description

试用助手的后端回复包含完整搜索结果摘要和末尾追问，但前端消息气泡只露出到“共导出 19 条结果，”附近，末尾“已保存到 txt 文件中。请问这个结果符合你的预期吗？”不可见。用户看到的试用回复与日志中的完整回复不一致。

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 - Teach A Skill In The Redesigned Flow
- **Affected requirements**: FR-010, FR-023
- **Gap identified**: 试用验证阶段必须展示真实 Agent 结果和后续用户确认问题；当前长 Markdown 回复在教学气泡中被布局/滚动行为截断。

### plan.md

- **Affected sections**: Project Structure for `frontend/src/screens/teaching` and `frontend/src/styles`
- **Impact**: Teaching chat Markdown must use layout rules that do not inherit plain-text wrapping behavior, and the chat viewport must scroll after long Markdown content settles.

### tasks.md

- **Affected tasks**: T059, T066, T067, T072
- **False completions**: Existing frontend tests checked state transitions and trial events but did not verify that a long trial assistant reply renders through its final question.
- **Missing tasks**: Add frontend regression coverage for a long Markdown trial reply with a table and final question.

## Root Cause Analysis

Teaching chat bubbles reused assistant Markdown inside a parent that forced `white-space: pre-wrap`. This could disrupt Markdown/table layout in teaching bubbles. The scroll-to-bottom hook also only reacted to message count changes, so long Markdown layout changes after render could leave the final lines below the visible area.

## Recommended Fix

1. Use a teaching-specific Markdown wrapper that resets `white-space` and constrains wide tables.
2. Scroll the teaching chat viewport after render frames and on content resize.
3. Add a regression test that the final question of a long trial assistant reply is present in the rendered trial stage.
