# Bug Report: Raw Trial Success Status Shown As Message

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 008-ui-stack-redesign
**Reported**: 2026-05-19

## Description

试用成功后，前端把 `trial.progress` 的内部状态值 `succeeded` 当成试用助手消息展示给用户。该事件应只更新试用成功次数和发布状态，不应把状态码作为聊天内容或进度文本显示。

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 - Teach A Skill In The Redesigned Flow
- **Affected requirements**: FR-010, FR-023
- **Gap identified**: 试用验证阶段需要展示用户可理解的结果和计数，但不应暴露内部状态码。`succeeded` 是 DTO 状态字段，不是用户文案。

### plan.md

- **Affected sections**: Project Structure for `frontend/src/state`; Phase 1 Design Summary
- **Impact**: Frontend event reducers must treat `status` as machine state and only create visible chat/progress entries from explicit user-facing fields.

### tasks.md

- **Affected tasks**: T058, T066, T072
- **False completions**: Existing trial success tests verified backend event projection but did not verify that raw status values stay out of user-visible messages.
- **Missing tasks**: Add frontend regression coverage that `trial.progress { status: "succeeded" }` updates `trialSuccessCount` without appending messages or progress log entries.

## Root Cause Analysis

`frontend/src/state/teachingStore.ts` used `payload.status` as the final fallback in `labelFromPayload()`. When a `trial_success` event projected to `trial.progress` with only `status: "succeeded"`, the store generated a visible trial assistant message from that status.

## Recommended Fix

1. Remove `status` from user-visible label fallback.
2. Only append teaching/trial chat messages when an explicit readable field exists (`headline`, `question`, `message`, `error`, or `result`).
3. Preserve trial success count and published state updates from `trial.progress`.
