# Bug Report: Learning Completion Toast Missing

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 008-ui-stack-redesign
**Reported**: 2026-05-19

## Description

后端技能学习完成后，日志显示 Programmer 已提交代码并进入完成路径，但前端没有弹出“学习完成”通知。用户只能看到阶段变化或需要刷新/切换视图，缺少完成提示。

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 - Teach A Skill In The Redesigned Flow
- **Affected requirements**: FR-010, FR-023
- **Gap identified**: US3 要求学习进度和结果在 redesigned flow 中可理解；完成事件已经被后端映射为 `trial_validation`，但前端没有把该事件转换为用户可见 toast。

### plan.md

- **Affected sections**: Project Structure for `frontend/src/state`; Phase 1 Design Summary
- **Impact**: The frontend state machine must translate backend teaching completion events into both stage state and notification state.

### tasks.md

- **Affected tasks**: T058, T059, T066, T071, T072
- **False completions**: Existing event-stream tests verified stage/preview state but did not verify the completion notification.
- **Missing tasks**: Add a frontend event-stream regression assertion that a `teaching.stage_changed` event to `trial_validation` renders the teaching toast.

## Root Cause Analysis

`frontend/src/app/AppShell.tsx` already rendered `useTeachingStore().toast`, but `frontend/src/state/teachingStore.ts` never set `toast` when handling learning completion. The `code_completed` / `review_passed` backend events were mapped correctly to `teaching.stage_changed` with `stage: "trial_validation"`, yet the frontend only updated `stage`, `run`, and `progressLog`.

## Recommended Fix

1. Set a teaching toast when scoped `teaching.stage_changed` moves to `trial_validation`.
2. Keep existing AppShell rendering and auto-dismiss behavior.
3. Extend AppShell event-stream tests to assert the toast title/body appears after the completion event.
