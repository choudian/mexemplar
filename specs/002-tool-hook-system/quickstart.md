# Quickstart: 工具执行 Pre/Post Hook 系统

## Prerequisites

- Worktree: `D:\develop\code\Exemplar\.worktrees\002-tool-hook-system`
- Feature spec: `specs/002-tool-hook-system/spec.md`
- Plan artifacts generated by `/speckit.plan`

## Implement

1. Add hook protocol types and args-freezing helper in `src/business/agents/hook_models.py`.
2. Extend `ToolDefinition` and `AgentConfig` in `src/business/agents/config.py`.
3. Update `src/business/agents/agent_loop.py` so batch/solo-interrupt `ToolDefinition` calls pass through the hook chain without changing 003 multi-tool semantics.
4. Move gate checks into pre_hooks in:
   - `src/business/agents/tools/builtin_general_tools.py`
   - `src/business/agents/tools/recording_data_tools.py`
   - `src/business/agents/tools/trial_tools.py`
5. Add focused tests in `tests/test_hook_protocol.py`.
6. Update active docs after code behavior is real:
   - `docs/ARCHITECTURE.md`
   - `docs/PROJECT_CONSTRAINTS.md`

## Targeted Validation

Run the focused protocol test first:

```powershell
uv run python -m pytest tests/test_hook_protocol.py -q
```

Run existing recording guard/regression tests touched by `query_data` and `analyze_image` boundaries:

```powershell
uv run python -m pytest tests/recording/test_recording_data_tools_noise_filtering.py tests/recording/filtering/test_recording_tools_no_sqlglot.py -q
```

Run Agent runtime smoke/regression coverage that does not require a live LLM key:

```powershell
uv run python -m pytest tests/integration/test_agent_loop_multi_tool_calls.py -q
uv run python -m pytest tests/integration/test_assistant_new_session.py -q
```

Run formatting and lint gates required by the constitution:

```powershell
uv run black --check src tests
uv run flake8 src tests
```

Before handoff, run static checks for stale semantics:

```powershell
rg -n "PreHookResult.*args|ToolCallContext.*result|只读浅拷贝|pipeline|流水线|改参" src tests
```

Expected result:
- No old args-pipeline contract remains in code or tests.
- `ToolCallContext` has no result/confirmation callback.
- Pre-hook gate tests prove handlers are skipped for rejected calls.
- `query_data` still allows harmless comments and semicolons inside string literals while rejecting existing rewrite/filter policy violations.
- Ordinary handler exceptions can still be observed by post_hook.
- Ordinary multi-tool batches still cascade `not_executed` after hook rejection or handler failure.
- Mixed interrupting batches still run no hook or handler and emit `invalid_model_output`.
- Solo interrupting `ToolSignal` still preserves existing AgentResult behavior and skips post_hook.
- Full-chain no-op hook overhead is within the 5 ms budget.
- A new global pre_hook can be mounted without changing tool handlers or AgentLoop engine code and within the SC-005 line budget.
- `programmer_tools.syntax_check`, `recording_data_tools.execute_code`, `tool_executor`, and `dynamic_tool_manager` remain outside hook migration.
