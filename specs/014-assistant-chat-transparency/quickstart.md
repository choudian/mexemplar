# Quickstart: 主助理对话透明与可控 — 验证路径

## 前提

- 在隔离 worktree 内开发：`cd .worktrees/014-assistant-chat-transparency`
- 前端：`cd frontend && npm install`（如需）
- 后端：`uv` 环境就绪

## 手动验收（按用户故事）

> 真实联调走 Tauri 应用（`npm run tauri:dev`）+ 已配置 LLM。前期演示脚手架（`assistantDemoStore` / `AssistantDemoView` / `DemoComposer`）是一次性原型，生产组件接好真实 store + 事件后移除（见 tasks T066），不作为长期预览态保留。

**US1 输入门控 + 停止（P1）**
1. 发起一个会持续一段时间的任务 → 运行期间无法再发送/唤醒；发送按钮变"停止"。
2. 点停止 → 当前回合在下一安全节点停下，进度变"已停止"，对话回到可输入；已产生内容保留。
3. 若该回合派了子任务 → 停止后子任务卡片变"已暂停"（无"主停子未停"残留）。
4. 助理反问（waiting_for_user）时 → 输入框可用，可正常回答。

**US2 排队（P2）**
1. 运行中在输入框打字 → 进入"编辑态"；回车或点别处 → 变"排队态"（整框排队样式）。
2. 回合自然结束 → 排队消息自动发出，无需手动发送。
3. 双击排队框 → 回编辑态，可改/追加；编辑态期间助理即便空闲也不外发。
4. 排队后点停止 → 排队消息退回普通草稿、不自动发。
5. 切到别的会话再切回 → 排队消息仍在。
6. 助理以反问结束时排队 → 排队消息作为对反问的回应自动发出（澄清确认）。

**US3 过程时间线（P2）**
1. 发起任务 → 出现默认折叠的过程区域，头部"正在处理"+转圈，不自动展开。
2. 手动展开 → 看到推理/工具调用/工具结果实时追加；最终回复单独正常显示、不重复。
3. 过程项超出限高 → 区域内部出现滚动条，页面整体不被撑长。
4. 重开该历史会话 → 仍可展开回看过程。

**US4 子任务卡片（P2）**
1. 派子任务 → 出现带动效的卡片，显示任务与"运行中"。
2. 双击卡片 → 抽屉展示该子任务完整过程（含工具与结果）。
3. 断连重连/重开会话 → 子任务列表与状态由权威端点恢复。

**US5 继续任务（P3）**
1. 停止一个跑着子任务的回合 → 卡片"已暂停"+"继续任务"。
2. 点"继续任务"（可填补充消息）→ 主助理被唤醒续跑，结果作为正常回复出现。
3. 子任务运行中时"继续任务"不可用；非本会话子任务被拒绝。


## 验收门槛（对应 Success Criteria）

- 运行期 0 例误唤醒；waiting_for_user 输入 100% 可用（SC-001）
- 停止后无"主停子未停"残留（SC-002）
- 编辑态排队 0 例提前外发；排队回合结束自动发出（SC-003）
- 每回合主助理与子任务过程均可查看、默认折叠、不撑长页面（SC-004）
- 暂停子任务可"继续任务"完成、无需重述（SC-005）
- 停止后历史 100% 保留已产生内容（SC-006）
- 非助理流程行为零变化、回归 100% 通过（SC-007）
- UI 文案 0 命中内部术语（SC-008）
