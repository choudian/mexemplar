## Product Lens Findings

### 3a. Problem Validation
问题清晰、用户亲述、痛点真实（黑盒/停不下/丢字/接不上）。无异议。

### 3b. User Value（P2 🤔）
P1（门控+停止）作为 MVP 切片价值最高、可独立交付，分层优先级合理。
**疑点**：US3 的"**完整实时**活动时间线"是成本/风险最高、但相对"粗粒度'正在做 X' + 子任务卡片"边际价值最不确定的一块（要改所有 Agent 共用的 `AgentLoop`）。用户已明确选实时——此处仅请**确认**该取舍在本期就要，而非先上粗粒度、后升级。

### 3c. Alternative Approaches
"继续任务=唤醒主助理复用 `continue_subagent`"是好简化（避免新编排）。停止用协作式取消是唯一安全解。无更优替代被漏看。

### 3d. Edge Cases & UX（P3 💡）
spec 边界覆盖良好。**缺口**：未定义"**停止中…**"过渡态与**重复点停止**的幂等行为——协作式取消有延迟，用户可能连点。建议补一个 stopping 过渡态 + 重复停止幂等。

### 3e. Success Measurement（P4 💡）
SC 多数可度量；SC-002"数秒"在 clarify 已标 Deferred，仍偏含糊。建议定为可测："停止点击 UI 即时反馈（<200ms）+ 在当前步骤返回后的下一安全节点生效 + 无'主停子未停'残留"。

## Engineering Lens Findings

### 4a. Architecture Soundness（E1 💡 高价值）
ContextVar 运行上下文优雅且守分层。**承重隐式不变量**：深度取消的正确性**完全依赖**"子代理/专员在与父**同一线程内同步**执行"（ContextVar 才能传播）。当前成立（`_run_delegated_executor` 同步调 `loop.run`，`task_worker` 不在委派路径）。但一旦将来任何委派改走线程/异步，**深度取消会静默失效**。建议：补一个**断言同线程委派**的门卫测试 + 在 `run_context.py`/委派处显式注释该不变量。

### 4b. Failure Modes（E2 💡）
- emit best-effort、不破坏主流程——good。
- **取消 Event 泄漏**：若 `end()` 因崩溃漏清，`session_id→Event` 表里的陈旧 Event 可能误取消**复用同一 session_id 的后续运行**。建议：`end()` 确保移除表项；并给每次运行一个**代际 token**，使陈旧 `set` 无法影响新一轮。

### 4c. Security & Privacy（E5 💡）
工具入参/结果进入 `assistant.activity`/`assistant.subagent` 载荷，可能夹带敏感数据（如某工具参数里的密钥/路径）。虽单用户本地，但仍经事件流与 UI。建议：让活动/子任务载荷**显式走 009 既有 payload safety allowlist/脱敏**，而非仅靠截断。

### 4d. Performance & Scalability（E4 💡）
实时逐步事件对长回合（assistant max_iterations=200）可能产生数百条事件。建议：① 在 `AgentLoop` 处**按 ContextVar 是否存在 gate 住 emit**（仅可观测时才发，避免 PM/Programmer/Trial 白发被 projector 丢弃的流量）；② 对单回合活动事件设上限/合并，防极端长回合刷爆前端 store。

### 4e. Testing Strategy
plan 测试面完整。补两条：E1 的同线程门卫测试；E3 决议后的"压缩历史回看"行为测试。

### 4f. Operational Readiness
单用户桌面、无迁移、回滚=revert，OK。

### 4g. Dependencies & Integration（E3 🤔 需拍板）
**FR-020 要求历史会话过程可回看**，但旧回合可能已被**大脑压缩/Segment 沉淀**，中间步骤消息不再完整保留。两者**直接冲突**：transcript 依赖既有中间消息重建，压缩后无法还原全量。需拍板历史保真度：全量（要求压缩不动 assistant tool 步骤）还是**尽力而为**（压缩过的回合显示"较早步骤已概要"）。建议取尽力而为并据此微调 FR-020/假设。

## Cross-Lens Insights

- **X1 💡（Scope × Risk）= P2 + E4**：实时全量 `AgentLoop` emission 是"高风险 × 边际价值不确定"的交汇点。建议把它作为**独立增量**、严格门卫+行为契约测试包住；并确认本期必要性（用户已选实时，确认即可）。
- **X2 💡（UX × Reliability）**："继续任务"是**确定性的用户按钮**，但实际由 **LLM 决定是否/对哪个子任务**调 `continue_subagent`。LLM 可能选错或不调。建议：续跑指令结构化（明确 subagent_id），并在续跑后**校验目标子任务确实从 suspended→active**；若主助理没去续跑，给用户明确兜底提示，而非静默无反应。
