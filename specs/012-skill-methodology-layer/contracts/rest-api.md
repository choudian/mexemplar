# REST API Contract: Skill Methodology Layer

Generated by `/speckit-plan` — Phase 1 output.

## 概览

本 feature 暴露的所有面向前端的 HTTP API 入口。Tool 域旧 API（`/api/skills/`，对应原"工具技能"三屏）保持不变（CC-005），新方法论域 API 走独立 prefix `/api/skills/methodology/` 与 `/api/specialists/{id}/equipment/`，与 Tool 域 API 路径不重叠。

所有请求必须带 `X-Mexemplar-Session: <runtime-token>` header（与既有 desktop_api 鉴权一致）；缺失或不匹配返回 401。

错误响应统一形态：
```json
{"error": "<short-token>", "message": "<user-friendly>"}
```
错误 token 集合（与守卫测试断言对齐）：
- `skill_not_found` (404)
- `skill_name_collision` (409，含 `occupied_skill_id`)
- `skill_source_segments_required` (400)
- `skill_source_segment_wrong_zone` (400)
- `skill_trigger_conditions_required` (400)
- `skill_protected_edit_requires_confirmation` (409，由 backend 主动 emit 高危确认事件后 service 阻塞)
- `skill_active_specialists_attached` (409，含 `affected_equipment_count` 与 `affected_specialist_ids`，由 backend 主动 emit 软删除高危确认事件后 service 阻塞)
- `skill_equipment_skill_not_active` (400)
- `unauthorized_tool_call` (403，未授权 specialist 调 create_skill_methodology)
- `bootstrap_skill_not_softdeletable` (403，FR-027a 链根受保护)

## 1. 方法论资产读取

### 1.1 List Active Skills

`GET /api/skills/methodology?sort=<key>&filter=<key>`

**Query Params**:
- `sort` (optional, default `recent_change`): `recent_change` | `load_count` | `referenced_count` | `equipped_count`（FR-029a 4 种排序模式）
- `filter` (optional): `never_referenced` | `not_referenced_30d`（FR-029a 2 类筛选）

**Response 200**:
```json
{
  "items": [
    {
      "skill_id": "skl_abc",
      "name": "周报生成方法论",
      "description": "...",
      "trigger_conditions": ["..."],
      "required_tools": ["..."],
      "version": 2,
      "chain_root_id": "skl_xxx",
      "origin": "user_edit",
      "is_protected": true,
      "loaded_count": 42,
      "referenced_count": 18,
      "equipped_count": 4,
      "last_referenced_at": "2026-05-20T10:00:00Z",
      "created_at": "2026-05-20T09:00:00Z"
    }
  ]
}
```

- `is_protected = true` 当 chain_root 的 `origin = system_bootstrap`（前端用以决定是否隐藏软删除按钮 + 编辑保存触发高危确认）
- `equipped_count` = `len(brain_skill_equipment WHERE skill_id = <当前 active 版本 id> AND status = 'active')`（含 assistant 本体 + 所有 specialist；FR-040 / SC-013 口径）
- 不返回 `body_markdown`（前端按需调 detail；CC-004 payload 不含正文全文）

## 2. 方法论资产写入（用户路径）

### 2.1 Edit Skill

`PUT /api/skills/methodology/{skill_id}`

**Request Body**:
```json
{
  "name": "...",
  "description": "...",
  "trigger_conditions": [...],
  "required_tools": [...],
  "body_markdown": "..."
}
```

**Response 200**:
```json
{
  "new_skill_id": "skl_v3",
  "version": 3,
  "chain_root_id": "skl_xxx"
}
```

**Error Cases**:
- 400 `skill_name_empty` / `skill_description_empty` / `skill_body_empty` / `skill_trigger_conditions_required`
- 409 `skill_name_collision` if 改 name 撞到现有同名 active（含 `occupied_skill_id`）
- 409 `skill_protected_edit_requires_confirmation` if 链根 origin = `system_bootstrap`：service 先 emit UI Event `assistant.confirmation`（actionType = `skill.edit_protected`），阻塞等待 user decision；用户拒绝 → 取消请求；用户确认 → service 继续走 supersede 接力（保护链根 origin 判定，详见 FR-027a）

事务边界：旧版本 → superseded、新版本 → active、所有装备关系切换到新版本，全部在单事务内（与 supersede 路径同模式）。

### 2.2 Soft Delete Skill

`POST /api/skills/methodology/{skill_id}/soft-delete`

**Response 200**:
```json
{
  "deleted_skill_id": "skl_xxx",
  "pruned_equipment_count": 4,
  "affected_specialist_ids": ["spec_a", "spec_b"]
}
```

**Error Cases**:
- 403 `bootstrap_skill_not_softdeletable` if 链根 origin = `system_bootstrap`（FR-027a）
- 409 `skill_active_specialists_attached` if 有装备者：service emit UI Event `assistant.confirmation`（actionType = `skill.soft_delete`，payload 含装备者名单 + 数量），阻塞等待 user decision；用户拒绝 → 取消请求；用户确认 → service 在单事务内执行装备关系裁剪 + 方法论落 `soft_deleted`

## 3. 装备关系管理

### 3.1 Get Equipment for an Entity

`GET /api/specialists/{specialist_id_or_assistant}/equipment`

`specialist_id_or_assistant`:
- `_assistant`（字面量）→ assistant 本体
- 任何 specialist UUID → specialist

**Response 200**:
```json
{
  "entity_type": "specialist",
  "entity_id": "spec_abc",
  "entity_name": "周报专员",
  "tool_whitelist": ["..."],
  "active_equipment": [
    {
      "skill_id": "skl_v2",
      "chain_root_id": "skl_xxx",
      "name": "周报生成方法论",
      "description": "...",
      "trigger_conditions": [...],
      "required_tools": ["..."],
      "missing_required_tools": ["..."],
      "equipped_order": 0,
      "equipped_at": "..."
    }
  ],
  "token_budget_estimate": 3287
}
```
- `missing_required_tools` 是该方法论的 `required_tools` 减去 specialist 的 `tool_whitelist`（assistant 本体口径下为全空）
- `token_budget_estimate` = 后端计算 fallback 值（前端本地估算优先，本字段供测试或对账用）

### 3.2 Update Equipment

`PUT /api/specialists/{specialist_id_or_assistant}/equipment`

**Request Body**:
```json
{
  "skills": [
    {"skill_id": "skl_v2", "equipped_order": 0},
    {"skill_id": "skl_v3", "equipped_order": 1}
  ]
}
```

**Behavior**:
- 计算 diff：
  - 新增装备（skill_id 不在当前 active 装备中）→ 新建一行 status='active'
  - 已存在装备但调序 → 更新 equipped_order
  - 当前 active 装备但不在新列表 → 标 status='unequipped', reason='user_unequip'
- 全部在单事务内执行
- 拒绝场景：
  - 400 `skill_equipment_skill_not_active` if 任一 skill_id 非 active 状态
- 不阻断 `missing_required_tools` 非空场景（FR-016 仅警告）

**Response 200**:
```json
{
  "active_equipment_count": 5,
  "newly_equipped": ["skl_v3"],
  "newly_unequipped": []
}
```

### 4.1 Get Bootstrap Status

`GET /api/skills/methodology/bootstrap-status`

**Response 200**:
```json
{
  "bootstrap_active_skill_id": "skl_xxx",
  "fallback_used": true,
  "seed_file_path": "src/business/brain/seed/how_to_create_skill_methodology.md",

```
