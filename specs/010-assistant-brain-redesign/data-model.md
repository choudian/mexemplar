## 新表（v11 migration）

### 1. `brain_segments`

Segment = 一段连续的"打开会话 → 聊一段 → 关闭/空闲/强制切换"。沉淀分析的单位。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `segment_id` | TEXT | PK | UUID |
| `session_id` | TEXT | NOT NULL, FK sessions | 所属会话 |
| `status` | TEXT | NOT NULL | `pending` / `distilling` / `completed` / `failed` |
| `retry_count` | INTEGER | DEFAULT 0 | 沉淀重试次数（不含崩溃重置） |
| `all_empty_retried` | BOOLEAN | DEFAULT FALSE | 全空结果是否已重试过一次 |
| `boundary_reason` | TEXT | | 触发 segment 边界的原因（`window_close` / `idle` / `new_session` / `token_limit`） |
| `message_id_start` | TEXT | | 第一条消息 ID（已封存时填充） |
| `message_id_end` | TEXT | | 最后一条消息 ID（已封存时填充） |
| `sealed_at` | DATETIME | | Segment 封存时间（转入 pending） |
| `distilling_started_at` | DATETIME | | 沉淀开始时间（转入 distilling） |
| `completed_at` | DATETIME | | 沉淀完成时间 |
| `created_at` | DATETIME | DEFAULT now | |
| `updated_at` | DATETIME | DEFAULT now | |

**状态机**:
```
[open] → pending (sealed) → distilling (CAS lock) → completed
                          ↗                        ↘ failed (retries exhausted)
         pending ←────────────────────────────── (manual retry / crash reset)
```

**索引**: `(session_id)`, `(status)` — 加速 worker 查询 pending 列表和 crash recovery。

**`open` 态表示**: `open` 不是持久化状态（不在上方 `status` 枚举内）。一个进行中的 Segment **不创建数据库行**——它由"消息表中尚未被任何已封存 Segment 覆盖的消息"隐式推导得到。`brain_segments` 行仅在 Segment 封存（转入 `pending`）时创建，此时一并填充 `message_id_start` / `message_id_end` / `sealed_at`。下一个边界事件（`new_session` / `window_close` / `idle` / `token_limit`）将"自上一个已封存 Segment 的 `message_id_end` 之后、尚未覆盖的全部消息"封存为新 Segment。因此应用被非优雅终止（进程被杀、断电）时，进行中的会话增量不会丢失：它没有易失的内存行，会在下次会话边界被正常封存并沉淀。

**沉淀写入原子性**: 一次成功沉淀产生的全部 `brain_memory_entries` INSERT，与该 Segment `distilling` → `completed` 的状态转换，MUST 在单个数据库事务内提交。崩溃发生在该事务 commit 之前 → 整体回滚 → Segment 停留在 `distilling` 状态，由崩溃恢复（扫描 `distilling` 并重置回 `pending`）正常重试，不残留半成品条目，再次沉淀也不会产生重复条目。

### 2. `brain_memory_entries`

所有 6 个分区的条目统一存储于此表，用 `zone` 字段区分。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `entry_id` | TEXT | PK | UUID |
| `zone` | TEXT | NOT NULL | `hot` / `persistent` / `archive` / `subconscious` / `failure` / `prediction` |
| `entry_type` | TEXT | | `event` / `insight`（沉淀 LLM 赋值，仅热区有效） |
| `content` | TEXT | NOT NULL | 条目内容 |
| `status` | TEXT | NOT NULL, DEFAULT `active` | `active` / `fading` / `invalidated` / `soft-deleted` |
| `origin` | TEXT | NOT NULL | `distillation` / `user_edit` / `system_migration` / `manual` |
| `scope` | TEXT | | 适用范围（自然语言描述，如"工作项目决策类"） |
| `reason` | TEXT | NOT NULL | 缘由（自动产物强制非空） |
| `source_segment_id` | TEXT | FK brain_segments | 来源 segment（蒸馏类条目） |
| `source_session_id` | TEXT | FK sessions | 来源会话 |
| `superseded_by` | TEXT | FK brain_memory_entries | 被哪条新条目取代（可空外键） |
| `loaded_count` | INTEGER | DEFAULT 0 | 注入助理上下文的次数 |
| `referenced_count` | INTEGER | DEFAULT 0 | LLM 回复中实际引用的次数 |
| `relevance_score` | REAL | DEFAULT 1.0 | 热区相关性评分（衰减用） |
| `verification_checkpoint` | TEXT | | 验证时间点（ISO 日期或事件描述）——预测区专用 |
| `verification_status` | TEXT | | `hit` / `miss` / `partial` / `expired`——预测区专用 |
| `verification_rationale` | TEXT | | 验证理由文本（LLM 一句话说明）——预测区专用 |
| `created_at` | DATETIME | DEFAULT now | |
| `updated_at` | DATETIME | DEFAULT now | |

**索引**: `(zone, status)`, `(source_segment_id)`, `(superseded_by)`, `(zone, relevance_score DESC)`.

**效果比公式**: `effectiveness = referenced_count / loaded_count`（loaded_count=0 时视为 0.0）。

**注意**:
- `soft-deleted` 条目不进入普通检索，但物理保留，可通过 `superseded_by` 链追溯。
- 预测区条目的 `entry_type` 留空；预测专用字段仅在 `zone='prediction'` 时有意义。
- `reason` 对 `origin='user_edit'` 或 `'manual'` 也必须非空（记录"用户手动修改/创建"）。

## 状态转换（Memory Entry）

```
active  ──[热区衰减]──→  fading  ──[decay router]──→ (move to archive/persistent)
  ↑                                                        or soft-deleted
  └──[manual retry / new distillation]
active  ──[失效信号]──→  invalidated  (still returned in retrieval, weight degraded)
active  ──[用户软删]──→  soft-deleted  (excluded from retrieval, history retained)
active  ──[用户编辑]──→  soft-deleted  +  new active entry (superseded_by link)
```
