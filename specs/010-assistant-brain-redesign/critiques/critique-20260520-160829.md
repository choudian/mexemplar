## Must-Address Verification

### [E1] 沉淀写入原子性 —— ✅ 已闭合

**要求**:沉淀的条目写入必须与 Segment `distilling → completed` 转换原子提交,避免崩溃产生重复条目。

**核对证据**:
- `spec.md` FR-021 末尾已增补:"Exactly-once delivery MUST further cover writing, not only triggering: the Memory Entry inserts produced by a successful distillation and the Segment's `distilling` → `completed` state transition MUST be committed within a single database transaction. If the process crashes before that transaction commits, the inserts MUST roll back as a unit ... MUST NOT result in duplicate Memory Entries when the Segment is re-distilled."
- `data-model.md` `brain_segments` 节已新增「沉淀写入原子性」说明,与 FR-021 表述一致(单事务、commit 前回滚、不残留半成品、不重复)。

**判定**:恰好一次"写入"语义现已与恰好一次"触发"并列明确;崩溃恢复路径(`distilling → pending`)与原子提交配合后不再产生重复。闭合。

### [E2] `open` 态 Segment 的表示与崩溃恢复 —— ✅ 已闭合

**要求**:明确 `open` 态 Segment 的表示形式,并覆盖进程被非优雅终止时进行中增量的恢复。

**核对证据**:
- `data-model.md` `brain_segments` 节已新增「`open` 态表示」说明:`open` 不是持久化状态,进行中的 Segment **不创建数据库行**,由"消息表中尚未被任何已封存 Segment 覆盖的消息"隐式推导;行仅在封存时创建。
- `spec.md` Edge Cases 已新增一条"进行中(`open` 态)Segment 的崩溃恢复":非优雅终止(进程被杀、断电)时进行中增量不丢失,下一次会话边界正常封存。

**判定**:`open` 态采用隐式推导(无易失内存行),消除了崩溃丢失整段增量的风险;data-model 与 spec Edge Case 两处表述一致。闭合。

### [E3] 效果比排序在 P1/P2 无数据来源 —— ✅ 已闭合

**要求**:注入排序不能以效果比为唯一键(P1/P2 期间 `referenced_count` 恒为 0),需定义兜底/混合排序并消除新条目冷启动饿死。

**核对证据**:
- `spec.md` Architecture Impact:注入排序改为"composite score",明确"MUST NOT use the effectiveness ratio ... as its sole key"——热区主排序 `relevance_score`、潜意识区主排序新近度、效果比仅作加权项;低 `loaded_count` 新条目获 exploration allowance;并明确"observable and verifiable from Phase P1 onward (per CC-009)"。
- `spec.md` 对应 Clarification(注入选取策略)已同步改写为复合评分。
- `research.md` 新增 Decision 11(大脑上下文注入排序策略),含 Rationale 与 Alternatives。
- `plan.md` P2 范围行已由"效果比排序"同步为"注入排序复合评分(relevance/新近度主排序 + 效果比加权项;`referenced_count` 计量在 P3 到位)"。

**判定**:CC-009 阶段独立可验证性恢复(P1/P2 排序退化为 relevance/新近度,仍可验证);冷启动饿死由 exploration allowance 消除;spec / research / plan 四处表述一致。闭合。

## New Finding This Run

### [E10] 💡 FR-018 "低效果比降权"措辞与 E3 的探索配额存在字面张力

**Lens**: Engineering — 4a Architecture Soundness(规格内部一致性)

E3 修订后,注入排序为复合评分,且**新条目(`loaded_count=0`,效果比 0.0)获得 exploration allowance**——即新条目不被降权,反而被保护性地保证有机会进入 top-N。

但 FR-018 仍保留原措辞:"the effectiveness ratio (referenced_count / loaded_count) MUST be used as a retrieval ranking signal — **entries with low effectiveness are deprioritized** but never excluded entirely."

字面读:一个全新条目效果比为 0.0(属于"low effectiveness"),FR-018 说它被"deprioritized";而 E3 说它获探索配额、不被饿死。两者存在张力。

可调和的解释是:FR-018 的"low effectiveness"应指"**经过足够注入曝光后**仍被 LLM 持续忽略"的条目(高 `loaded_count`、低 `referenced_count`),而非从未被注入、效果比尚无意义的新条目。FR-018 本身也说效果比是"a signal"(一个信号,可与复合评分兼容)且"never excluded entirely"(与探索配额兼容)——所以并非真冲突,只是措辞不够精确,易被误读。

**严重度说明**:💡 而非 🎯。Architecture Impact 段与 research Decision 11 对实际机制的描述清晰且权威,`/speckit-tasks` 生成注入排序任务时会以它们为准,不会因 FR-018 的宽松措辞而把缺陷写进 tasks.md。这是一条规格内部一致性的收紧建议。

**Suggestion**: 把 FR-018 中"entries with low effectiveness are deprioritized but never excluded entirely"收紧为类似:"entries whose effectiveness stays low *after sufficient injection exposure* are deprioritized; entries not yet injected enough times to have a meaningful ratio are not deprioritized on that basis — see the composite-score injection strategy in Architecture Impact / research Decision 11"。使 FR-018 与 E3 的复合评分 + 探索配额模型显式一致。
