## Executive Summary

本轮审查基于前两轮 remediation 后的 spec、plan、research、data model、contracts 和 quickstart。整体方向已经明显收敛：trace arm lifecycle、ordinary log 边界、vision metadata、Agent Flow ephemeral detail、真实 Grand Tour 的预算/报告/只读凭据要求都已经写进设计工件；未发现需要推翻功能目标或拆回 `/speckit.specify` 的根本问题。

但仍有三类问题应在生成 tasks 前写回文档：第一，真实 Grand Tour 和诊断 redactor 的只读 credential/provider 覆盖仍按 broad category 描述，当前代码中还存在 settings connection validation、Skill Composition、compression、embedding 等直接 credential/model 入口，足以绕过拟议只读路径或 trace/source 盘点；第二，raw debug 数据的“不持久化”合同没有覆盖 HTTP/WebView cache 和前端状态持久化；第三，embedding/model-call 是否属于 trace coverage 在工件之间仍不清晰。这些都是可修订的合同缺口，因此结论为 **PROCEED WITH UPDATES**。

### Review Basis

- 治理依据：`.specify/memory/constitution.md` 的分层、配置/密钥安全、可验证交付与活文档原则。
- 评审工件：`spec.md`、`plan.md`、`research.md`、`data-model.md`、`quickstart.md`、`contracts/*.md`、两份既有 critique。
- 代码核验点：
  - `src/desktop_api/orchestrator_runtime.py`、`src/business/brain/background_worker.py`、`src/business/services/skill_composition/service.py`、`src/business/memory/compression_handler.py`、`src/business/memory/assistant_memory.py`、`src/business/services/settings_actions_service.py` 仍各自读取 credential 或创建模型客户端。
  - `src/business/memory/assistant_memory.py` 直接使用 `OpenAIEmbeddings.embed_query()`，不经过 `LangChainLLMClient`。
  - `frontend/playwright.config.ts` 当前默认未开启 trace/video/screenshot，但 real-tour 新配置尚未明确 artifact policy。

## Engineering Lens Findings

### 4a. Architecture Soundness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | Real Grand Tour 的 side-effect-free credential provider 仍按 `main/vision/background/redactor` broad category 描述，但现有代码还有 settings connection validation、Skill Composition LLM factory、compression LLM、embedding client 等 credential/model construction callsites。Grand Tour 又包含 settings 与 skills/compositions 场景；如果这些路径继续调用 ordinary getter，就可能触发 keyring migration/write 或绕过 mutation audit。 | 在 `plan.md` 和 `contracts/grand-tour.md` 增加完整 credential/model construction inventory，以 `rg get_ai_.*api_key|OpenAIEmbeddings|LangChainLLMClient` 结果为验收清单；real-tour mode 必须向每个会被场景触达的路径注入只读 provider，未覆盖即 unmet prerequisite 失败。 |
| E2 | 🎯 | Trace coverage 工件没有明确 embedding 是否是“supported model-call source”。Spec/SC 要求每个 supported model-call source 出现在 trace 中，redactor 又覆盖 embedding credential；但 data model 的 `method` 只有 `chat/chat_with_tools/multimodal`，research 的统一边界也不覆盖 `OpenAIEmbeddings.embed_query()`。 | 在 `spec.md`/`data-model.md`/`plan.md` 做明确决定：若 embedding out of scope，收窄 SC-004 和 “model-call source”措辞；若 in scope，新增 `method=embedding`、安全 payload policy、source context 和直接 embedding call guard。 |

### 4b. Failure Mode Analysis

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 💡 | 计划用 `contextvars` 关联 source/session/workflow，但 Python `contextvars` 不会自动跨 `threading.Thread` 或某些 executor 边界传播。background worker、trial/recording 相关线程或 future 可能退化为 `unknown`，影响 30 秒定位和 coverage 证据。 | 在 plan 的 P2/P3 中增加 context propagation helper 或 thread-entry wrapper，并用并发/嵌套/后台线程测试证明 source 不串线、不丢失；确实不可得时才标记 `unknown`。 |

### 4c. Security & Privacy Review

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E4 | 🎯 | Raw debug 数据禁止进入 SQLite/DuckDB/log/SSE，但 contracts 没要求 debug GET responses 设置 `Cache-Control: no-store`，也没禁止前端把 raw trace/reference 放进 persisted Zustand、localStorage、URL 或浏览器历史。WebView/HTTP cache 可能成为持久化旁路。 | 在 `contracts/debug-api.md` 和 plan Validation Strategy 增加 no-store/no-cache response header、frontend memory-only state、disable/clear 时客户端 purge、禁止 raw 内容进入 URL/localStorage/sessionStorage 的测试。 |

### 4d. Performance & Scalability

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E5 | 💡 | Trace records 有单条/聚合 byte budget，但 reference expansion 是 on-demand response 且“不加入 trace cache”，没有 per-response 大小上限或 chunking。大型 reference 会造成 UI/sidecar 内存压力，也难以维持“可安全清空”的体验预期。 | 为 `GET /api/debug/references/{id}` 增加响应 byte/line limit 或 chunked read 合同，超限显示 explicit truncation/chunk token；复用已有大字段分段读取模式时写入 plan。 |

### 4e. Testing Strategy

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E6 | 💡 | Debug retention limit 键是 hidden unified config，但计划没有列出默认值落点、非法值回退测试或配置模板/活文档同步点。实现者可能只在 service 内硬编码，违反统一配置治理。 | 在 `plan.md` 的 configuration/data impact 中指定 defaults/schema/accessor 更新文件和非法值测试；确保不直接读配置文件、不在模块硬编码。 |
| E7 | 💡 | Real Grand Tour 报告已禁止 raw prompt/screenshot，但 Playwright real-tour 新配置尚未明确 trace/video/screenshot/error attachments policy。失败时默认 artifacts 或自定义录制输出可能携带当前桌面隐私。 | 在 `contracts/grand-tour.md` 增加 artifact policy：默认关闭 Playwright trace/video/screenshot，或仅允许专门无敏感目标的最小截图；所有 output 走 sentinel sanitization。 |

### 4f. Operational Readiness

现有计划已覆盖预算、cleanup、summary report、keyring mutation count 和三次同 commit/journey 证据。E1/E7 修订后，运营证据链足够进入任务拆分。

### 4g. Dependencies & Integration Risks

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E8 | 💡 | Direct provider invoke guard 目前只在文字上要求“受支持路径不得绕过”，但未指定 guard 的检测范围和例外登记方式。随着 brain/composition/memory 路径增加，后续很容易重新绕过统一边界。 | 在 `tests/guardrails` 计划中增加静态扫描 allowlist：所有 `.invoke(`、`embed_query(`、`LangChainLLMClient(`、`OpenAIEmbeddings(` 和 credential getter callsites 必须在观察边界或只读 provider inventory 中登记。 |

## Recommended Edits

### Must-Address Before `/speckit.tasks`

1. **E1 / X1 - credential and model construction inventory**
   - 修改 `plan.md` 的 Source Code / Validation Strategy，列出所有 credential getter、model client、embedding client、settings connection validation callsites。
   - 修改 `contracts/grand-tour.md`，要求 real-tour mode 覆盖 settings validation、skills/compositions、compression、background、vision、embedding/redactor 等实际触达路径；未覆盖时以 unmet prerequisite 失败。
   - 增加静态 guard：新增或既有 model/credential callsite 必须登记为 normal runtime、read-only real-tour provider 或明确 out-of-scope。

2. **E2 - embedding trace scope**
   - 修改 `spec.md` 的 SC-004 和相关 “model-call source” 措辞，明确 embedding 是否纳入 trace。
   - 若纳入：更新 `data-model.md` 的 `LLMTraceRecord.method`、source、payload budget 和 tests。
   - 若不纳入：明确 trace 覆盖指 text/tool/vision LLM calls，embedding credential 只属于 redaction inventory。

3. **E4 / X2 - raw debug cache and frontend persistence**
   - 修改 `contracts/debug-api.md`，要求所有 raw debug endpoints 返回 `Cache-Control: no-store` 等防缓存头。
   - 修改 `plan.md`/quickstart，要求 debug UI raw state 只留内存，disable/clear/route cleanup 时 purge，不进入 localStorage/sessionStorage/URL/persisted store。
   - 增加 API header、frontend storage scan 和 disable 后客户端状态清理测试。

### Strong Recommendations

1. **P1**: 增加固定 baseline fixtures，降低验收解释成本。
2. **P2**: 对齐手动输入长草稿的折叠语义。
3. **P3**: 明确 hidden debug route 的人工访问方式。
4. **P4/X3**: 将 real-tour skills/compositions 场景收敛为具体动作和允许副作用。
5. **E3**: 给 context propagation 加线程/并发测试。
6. **E5**: 给 reference expansion 加响应预算或 chunking。
7. **E6**: 指定 debug hidden config defaults/schema/accessor 落点。
8. **E7**: 明确 real-tour Playwright artifact policy。
9. **E8**: 把 direct provider/credential callsite 静态扫描做成 guardrail。
