## Executive Summary

本轮审查针对上一份 critique 修订后的规格和计划进行复核。上一轮识别的主要风险已经得到实质回应：视觉调用已被要求迁入统一观察边界；Assistant delegation 原文被改为 trace-enabled 的临时 detail；disable/re-enable 使用 epoch purge；普通日志禁 raw；Grand Tour 采用固定安全旅程、预算和只读 credential 合同。这些修订使总体架构方向成立，长粘贴 slice 也已具备进入任务拆分的质量。

但整个 feature 仍不应直接进入 `/speckit.tasks`。当前文档没有给开发者一个可执行、可观察且不会跨重启误采集的 trace 启停合同；`SC-012` 又把正常产品必须发送的 `assistant.message.content` 一并禁止；只读 credential/redactor 约束尚未贯穿真实创建模型客户端的启动与 vision 路径；可选诊断采集失败不得影响正常 LLM 工作的规则也未定义。这些均可通过规格/计划修订关闭，不要求推翻功能目标，因此结论为 **PROCEED WITH UPDATES**。

### Review Basis

- 治理依据：`.specify/memory/constitution.md`、`docs/PROJECT_CONSTRAINTS.md`。
- 评审工件：`spec.md`、`plan.md`、`research.md`、`data-model.md`、`quickstart.md`、`contracts/*.md`、既有 critique。
- 现状核验：
  - `src/business/services/settings_service.py` 的可修改设置白名单没有 `debug.trace.*`；`src/data/unified_config.py` 的 observer 仅在 `set()` 时通知。
  - `src/desktop_api/ui_events.py` 注册的 `assistant.message` 允许 `content`，`src/desktop_api/assistant_runtime.py` 会把正常用户可见 assistant 内容发布到该事件。
  - `src/desktop_api/orchestrator_runtime.py` 仍通过 `config.get_ai_api_key()` 构造真实 LLM 客户端；`src/business/agents/tool_helpers.py` 的 vision factory 仍通过 `get_ai_vision_api_key()` 取得凭据。
  - `src/data/unified_config.py` 的 `get_ai_api_key()` 包含明文迁移写 keyring 的分支，而 `get_ai_vision_api_key()` 可从普通配置字段返回视觉 key。

## Engineering Lens Findings

### Architecture Soundness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | Trace 生命周期依赖 enabled-to-disabled transition，但当前计划仅新增配置 accessor 且明确不进入普通 Settings UI；现有设置 API 不允许写 `debug.trace.*`，配置 observer 也只有走 `UnifiedConfigManager.set()` 才触发。因而同进程 disable/re-enable、原子 purge 与 mid-flight 拦截没有已定义的实际控制通路。 | 在 `plan.md` 与 `contracts/debug-api.md` 明确启停命令/端点/诊断页 bootstrap 合同及 ownership：只能经 business facade 调用 `UnifiedConfigManager.set()` 并驱动 `DebugInspectorService` epoch transition；补 API/UI/auth 与 `enable -> capture -> disable -> enable` 链路测试。 |
| E2 | 🎯 | `SC-012` 要求 ordinary public UI event output 中零 `raw model content`，但现有且必要的产品合同通过 `assistant.message.content` 向 React UI 发送 assistant 的用户可见回复。按当前成功标准实现，要么测试必然失败，要么会错误移除正常聊天输出。 | 将 `SC-012` 改为禁止 **diagnostic-only** raw prompt、非用户可见 model trace、raw handoff/media/correlation 与 secret 进入公共事件；明确既有用户可见 assistant message 内容不属于新增 debug 泄漏。同步 guardrail 的断言措辞。 |

### Failure Mode Analysis

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 🎯 | Trace 被定义为纯观察能力（`CC-006`），但计划未定义当 capture context、redaction、序列化或 bounded buffer 写入失败时的业务行为。若观察层异常冒泡，启用诊断会改变 Assistant/Teaching/brain 的正常 LLM 结果与失败面。 | 在 `plan.md`、`research.md` 与 debug contract 中增加 failure isolation：诊断采集失败必须丢弃该诊断 detail 或写安全 omission/status，不得阻止或替换原模型调用/结果；对 pre-call、post-call、redactor 与 buffer 故障增加注入测试。 |

### Security & Privacy Review

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E4 | 🎯 | 文档规定 Grand Tour 使用 side-effect-free credential resolver，并规定 redactor 覆盖主/视觉/embedding key，但尚未指定该 resolver/secret source 如何贯穿真正创建客户端的路径。当前 sidecar orchestrator factory 调用可能迁移写入的 `get_ai_api_key()`，vision factory 调用可从普通配置读取 key 的 `get_ai_vision_api_key()`；若只新增 helper 而未替换这些入口，FR-028 与零泄漏门卫仍无法成立。 | 在 `plan.md` 的 source impact 与 `contracts/grand-tour.md` 中登记 main/vision/background/redactor 的 credential-provider 注入路径，要求 real-tour mode 和 redactor 均只能使用无迁移、无明文配置回退、无 write/delete 的 secret snapshot/resolver；覆盖 sidecar bootstrap、vision 和后台调用的 mutation/sentinel 测试。 |

### Performance & Scalability

当前记录数、单条 bytes、合计 bytes、淘汰和 oversized omission 的设计已足以约束本地单进程 MVP；后续实现需按合同测试实际 retained byte accounting。

### Testing Strategy

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E5 | 💡 | `FR-009`/`FR-011` 描述每次请求可以看到提交的文本和“full recorded input/output”，但 `FR-013`、data model 和 API contract 正确允许超预算时只返回 `oversized_omitted`。需求层仍存在可被测试误读的冲突。 | 在 `FR-009` 与 `FR-011` 显式加入“在 retention budget 内展示全文，超限显示 omission record”的例外，与 `SC-013` 对齐。 |
| E6 | 💡 | 现有日志禁 raw 要求覆盖正常路径，但 provider 异常字符串或 traceback 也可能回显 endpoint/auth/raw request；当前验证描述未明确异常日志样本。 | 在 Validation Strategy 加入 provider/vision/delegation 异常注入与 captured-log sentinel 检查，确保失败日志同样只保留安全摘要。 |

### Operational Readiness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E7 | 💡 | Grand Tour 要求 `credential_mutation_count = 0` 和 fingerprint 不变，但合同未说明跨真实 sidecar 进程如何可靠观测短暂 `set_password/delete_password` 尝试；仅比较运行前后 fingerprint 捕捉不到写回原值或写后回滚。 | 在 runner 合同中指定可注入 keyring adapter/audit guard 或隔离 service-name proxy，并在 controlled failure tests 中证明对 sidecar 内部 mutation attempt 的检测覆盖。 |

### Dependencies & Integration Risks

现有 `UI_EVENT_REGISTRY` 已提供 Grand Tour 计划依赖的 readiness/assistant/recording/teaching/trial/settings 安全事件面；除 E2 的成功标准措辞冲突外，本轮未发现需要扩大公共事件 payload 的新理由。

## Recommended Edits

### Must-Address Before `/speckit.tasks`

1. **P2 / E1 / X1 - trace activation lifecycle**
   - 修改 `spec.md` 的 FR-008、FR-013A、CC-003 与验收场景，定义启用、持续提示、关闭、重启默认状态。
   - 修改 `plan.md` / `contracts/debug-api.md`，增加由 business facade 拥有的受鉴权 trace control path；明确是否使用 `UnifiedConfigManager.set(..., persist="runtime")`。
   - 增加启用前警示、同进程 disable/re-enable、重启不自动 raw-capture 或明确确认的测试合同。

2. **E2 / X2 - public event acceptance wording**
   - 修改 `spec.md` 的 `SC-012`，将 `raw model content` 改为 `diagnostic-only raw model trace content that is not already required as user-visible product output` 或等价中文约束。
   - 同步 `plan.md` guardrail 表述，避免测试阻断 `assistant.message.content` 的合法 UI 输出。

3. **E3 - observation failure isolation**
   - 在 `spec.md` 的兼容约束或 `plan.md` 的 P2 slice 中加入：capture/redaction/buffer/correlation failure 不得影响原 LLM 调用和业务流程，仅允许安全的诊断缺失状态。
   - 在 `contracts/debug-api.md` / Validation Strategy 加入 fault-injection 测试。

4. **E4 / X3 - credential resolver integration**
   - 修改 `plan.md` 的 source tree/architecture，列出 `src/desktop_api/orchestrator_runtime.py`、vision client factory 和所有 background model factory 的 credential-provider 接入职责。
   - 修改 `contracts/grand-tour.md`，规定 real-tour sidecar bootstrap 不能触达带 migration fallback 的普通 getter；redactor 的 secret inventory 同样不得为了脱敏而触发迁移或明文配置读取。
   - 增加 main/vision/background/bootstrap 的 keyring mutation 和 sentinel 验证。

### Strong Recommendations

1. **P1**: 增加可保存的现状基线。
2. **P3**: 增加安全的 manual run report 格式与保存方式。
3. **P4**: 明确独立 slice 可否独立合并/发布。
4. **E5**: 将 oversized omission 例外上提到 FR-009/FR-011。
5. **E6**: 覆盖 provider exception/traceback 的日志脱敏。
6. **E7**: 定义跨 sidecar mutation-attempt 的可观测实现。
