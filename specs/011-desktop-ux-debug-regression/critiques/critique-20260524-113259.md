## Executive Summary

本轮审查基于前三轮 critique remediation 后的 `spec.md`、`plan.md`、`research.md`、`data-model.md`、`quickstart.md` 和三个 contracts。上一轮剩余的阻断项已经被实质关闭：credential/model construction inventory 已覆盖 settings validation、skill composition、compression、embedding 和 redactor；embedding/vectorization 已明确排除在 trace record 之外但进入 provider/redaction inventory；raw debug 数据已禁止进入 HTTP/WebView cache、URL 和前端持久化状态；reference expansion、artifact policy、baseline fixtures 与 runtime-only trace lifecycle 也已形成可测试合同。

## Engineering Lens Findings

### 4a. Architecture Soundness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 💡 | `plan.md` 与 `contracts/grand-tour.md` 已完整列出 settings validation、skill-composition、compression、embedding/redactor 等 provider inventory，但 `spec.md` 的 `FR-028` / `CC-004` 仍主要点名 main/vision/background/redactor。虽然不冲突，但 mandatory requirement 的措辞比计划弱。 | 可选地同步 `FR-028` / `CC-004`，明确 real-tour 可触达的 settings validation、skill-composition、compression、embedding credential lookup 也必须走只读 provider 或在场景前显式 skip。 |
| E2 | 💡 | 计划要求 provider inventory guard，但还没有指定 inventory artifact 的位置和格式；如果只散落在测试代码里，后续新增 callsite 时审查成本会变高。 | 在任务阶段新增一个明确 inventory/allowlist 文件或测试数据结构，登记每个 `get_ai_*api_key`、`LangChainLLMClient`、`OpenAIEmbeddings`、`.invoke(`、`embed_query(` callsite 的分类和处理状态。 |

### 4b. Failure Mode Analysis

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 💡 | Observation failure isolation 已定义得很清楚，但 disable/clear 属于安全控制动作，不应按普通 observation failure 处理；文档要求原子 purge，但未显式说明 purge 过程中发生异常时如何 fail closed。 | 在任务或合同补一句：disable/clear 应先使 epoch 不可读/不可写，再执行 best-effort buffer cleanup；即使 cleanup 抛错，旧 epoch 也必须不可读取，API 返回安全错误或 disabled 状态。 |

### 4c. Security & Privacy Review

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E4 | 💡 | Redaction inventory 依赖“实际模型/runtime factory 注册的 credential/token snapshot”。如果某个 provider 在运行中轮换 credential，旧 snapshot 与新 snapshot 的生命周期需要实现时谨慎处理。 | 在 debug redactor 任务中覆盖 credential registration/update 的测试：新 client 注册新 secret 后新旧 sentinel 均不泄漏，且注册过程不调用 migration-capable getter。 |

### 4d. Performance & Scalability

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E5 | 💡 | Trace `retainedBytes`、aggregate budget 与 redaction 顺序有关；若先统计 raw、后存 redacted，预算可能和实际内存不一致；若先存 raw 再 redaction，则增加短暂泄漏面。 | 在 buffer 任务中规定 retained byte accounting 基于 redacted retained payload，且 buffer 永不保存 pre-redaction payload；oversized 判断在保留前完成并产生 omission record。 |

### 4e. Testing Strategy

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E6 | 💡 | Validation Strategy 已列出大量 guardrail，任务阶段如果不分层，很容易形成一个难定位的大测试。 | 将 guardrail 拆成命名清楚的测试组：provider inventory、debug no-store/storage、ordinary log no-raw、public SSE no diagnostic raw、epoch lifecycle、failure isolation、real-tour artifact sanitization。 |

### 4f. Operational Readiness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E7 | 💡 | Real-tour summary report 默认不提交仓库，但三次发布证据需要在 PR/release 中被引用；证据存放与引用方式仍可能因团队习惯漂移。 | 在 quickstart 或 docs 更新任务中说明 PR/release 只引用 summary 的安全字段和本地路径/附件策略，不复制 prompt、截图、录制正文或完整敏感路径。 |

### 4g. Dependencies & Integration Risks

当前 contracts 已避免扩大公共 SSE raw payload，并用 existing product events 驱动 Grand Tour；provider inventory 也已经要求静态扫描新增 callsite。除 E2 的 artifact 化建议外，本轮没有新的 integration blocker。

## Recommended Edits

这些不是进入 `/speckit.tasks` 的阻断项；可以作为 task generation 时的补强点。

1. **E1 / X1 - spec inventory alignment**  
   可选更新 `spec.md` 的 `FR-028` / `CC-004`，把 settings validation、skill-composition、compression、embedding credential lookup 和 redactor 纳入 real-tour reachable credential/provider boundary，或在 `tasks.md` 明确引用 `plan.md` 的 Credential And Provider Inventory。

2. **P3 / X2 - concrete live journey fixture**  
   在任务中要求创建固定 `liveJourneyId`、无敏感测试页面/窗口、字段、输入文本、动作顺序和终态断言；Grand Tour page object 以此为唯一发布证据路径。

3. **E2 / E6 - maintainable guardrails**  
   将 provider inventory 和 no-leak guard 拆成可维护的 allowlist/test data，而不是只在测试断言中散写字符串扫描。

4. **E3 / X3 - disable/clear fail-closed**  
   补充 debug service 行为：disable/clear 先让旧 epoch 不可读不可写，再执行 cleanup；cleanup 异常不得让旧 raw 数据重新可见。

5. **E4 / E5 - redaction and byte accounting details**  
   覆盖 credential snapshot rotation，并规定 retained byte accounting 基于 redacted payload；buffer 不保存 pre-redaction 内容。
