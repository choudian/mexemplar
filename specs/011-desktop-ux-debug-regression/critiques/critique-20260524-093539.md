## Executive Summary

该规格对三类开发体验问题给出了清晰的可见行为、隐私取舍和模块边界：长粘贴交互定义成熟，debug REST 与公共 SSE 的隔离方向正确，真实 Grand Tour 也明确了费用、录制与 keyring 不变式。但目前还不能进入 `/speckit.tasks`：计划把“现有 transition 足以返回交接详情”和“`LangChainLLMClient.chat*()` 足以捕获所有模型调用”当作已验证事实，而当前代码分别在 Assistant 委派详情与视觉调用上直接反证；同时现有 raw DEBUG 日志、trace disable 生命周期和 Grand Tour 只读凭据路径没有闭合安全合同。上述问题可在规格/计划层修正，无须推翻功能目标，因此结论为 **PROCEED WITH UPDATES**。

## Engineering Lens Findings 🔬

### Architecture Soundness
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | 计划在 `LangChainLLMClient.chat()` / `chat_with_tools()` 采集所有受支持调用，但 `invoke_vision_model()` 当前直接执行 `vision_client.llm.invoke(...)`；`data-model.md` 又明确列出 `vision` 来源。实现照计划推进会遗漏视觉调用，违反 FR-009/SC-004。视觉请求还包含 base64 screenshot，单纯按 200 条限量不能约束内存与隐私暴露量。 | 在 `research.md`/`plan.md` 指定统一可观测 provider invocation API，并把视觉路径迁入该边界；列出所有直接 invoke 的审计门卫。为多模态输入明确展示/留存政策及总字节上限，例如不在列表/详情保留完整 image data URL，改为受控元数据或独立受限查看能力。 |
| E2 | 🎯 | `plan.md` 声称 Agent Flow 读取现有 Assistant delegation handoff/result payload；实际 `assistant_delegation_started` 只保存 `agent_type`，结束 transition 只保存结果类型/成功/错误，任务文本与 `result_text` 并未进入 transition。无法满足 FR-021 的委派任务/返回详情，同时又不能把 debug-only raw 内容新增长久持久化。 | 在 `plan.md`/`data-model.md` 明确：trace 开启时由业务层在委派边界捕获 redacted、bounded、process-local flow detail，并关联现有 transition id；持久化 transition 仅继续作为权威状态事实。补充 started/completed/failed 的 link/unlinked 测试。 |

### Failure Mode Analysis
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 🎯 | 数据模型写明 disable 后旧 raw trace 不可读取，但当前设计仅描述 disabled 时拒绝 capture/read，没有定义从 enabled 切到 disabled 时如何销毁已存 buffer。若关闭后再次开启，同一进程中的旧记录可能重新可见。并发进行中的模型请求也没有开关切换规则。 | 在 `data-model.md`/`contracts/debug-api.md` 定义 disable transition 必须原子 purge trace/correlation/extra flow detail 或推进不可复用 epoch；定义 mid-flight completion 在 gate 已关闭时不得写回。加入 `capture -> disable -> re-enable -> 404/empty` 与并发关闭测试。 |

### Security & Privacy
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|

## Recommended Actions

### 🎯 Must-Address (Before Proceeding)

1. **P4**: 修改 `spec.md` 的 Real Grand Tour 场景与 SC-006，新增一条安全、可重复的人工 live-capture 操作脚本及终态断言；同步 `contracts/grand-tour.md`。
2. **E1**: 修改 `research.md` 与 `plan.md` 的采集边界说明，将视觉调用及所有 direct provider invocation 纳入统一 trace 边界；在 `data-model.md` 定义多模态内容的容量/展示政策。
3. **E2**: 修改 `plan.md`、`data-model.md` 与 `contracts/debug-api.md`，为 Assistant delegation 的 task/result detail 定义仅在 trace gate 开启时存在的进程内捕获来源，避免误称 existing persisted payload 已包含原文。
4. **E3**: 修改 `data-model.md` 与 `contracts/debug-api.md`，把 disable 定义为 purge/epoch 边界，并补 disable-reenable 与 mid-flight 测试要求。
5. **E4**: 修改 `plan.md` 的 P2/Validation Strategy，明确现有 raw LLM 与 delegation 日志必须移除或脱敏，并补齐主模型、视觉模型、授权材料及 runtime token 的 redaction inventory 与日志门卫测试。
6. **E7**: 修改 `plan.md` 与 `contracts/grand-tour.md`，规定 real-tour credential 获取必须是不会触发 keyring migration/write/delete 的只读路径，并要求自动验证 mutation 不变式。

### 💡 Recommendations (Strongly Suggested)

1. **P1/P2**: 在 `spec.md` 和 `plan.md` 补充问题基线，并按 composer/debug/real-tour 划分独立交付门槛。
2. **P3**: 在 debug UI/API 合同中标记 ephemeral 与 persisted 内容，明确 `DELETE /api/debug/traces` 不删除既有 workflow transition。
3. **P5/E5**: 为 raw buffer 和 real-tour 引入资源、时间及调用预算。
4. **E6**: 对 timeout/cancel/cleanup/keyring invariant 添加受控自动测试，而不是仅依赖手动付费执行。
5. **E8**: 在 Grand Tour 合同完成公共事件终态断言矩阵，避免实现阶段临时扩大 SSE 数据面。
