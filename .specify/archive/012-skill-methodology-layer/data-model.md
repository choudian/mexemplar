# Data Model: Skill Methodology Layer

Generated by `/speckit-plan` — Phase 1 output.

## 概览

所有新表在 **v12 migration** 中一次性创建。本 feature 的数据资产完全位于 SQLite 大脑命名空间，与 010 v11 的 `brain_segments` / `brain_memory_entries` / `brain_specialists` 并列；DuckDB 与录制数据不涉及。

Migration v12 还负责"如何创建方法论"内置方法论的 bootstrap 写入（详见 D9 / FR-027 / FR-027b）。

## 新表（v12 migration）

### 1. `brain_skills`

方法论资产主表。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `skill_id` | TEXT | PK | UUID（与 010 同模式） |
| `name` | TEXT | NOT NULL | 方法论名称（单串） |
| `description` | TEXT | NOT NULL | 一句话描述（单串） |
| `trigger_conditions` | TEXT | NOT NULL | JSON array of strings（≥1 条非空，详见 FR-024b） |
| `required_tools` | TEXT | NOT NULL | JSON array of strings（允许空 list） |
| `body_markdown` | TEXT | NOT NULL | 正文 Markdown（单串） |
| `status` | TEXT | NOT NULL, DEFAULT `active`, CHECK (`status` IN ('active', 'superseded', 'soft_deleted')) | 状态机封闭枚举 |
| `origin` | TEXT | NOT NULL, CHECK (`origin` IN ('system_bootstrap', 'user_edit', 'assistant_tool_call', 'specialist_tool_call', 'external_import')) | 创建来源封闭枚举（FR-006a / SC-025） |
| `parent_skill_id` | TEXT | FK brain_skills(skill_id) | 被谁 supersede 出来；NULL = 链根 |
| `superseded_by` | TEXT | FK brain_skills(skill_id) | 被哪条新版本取代；NULL = 当前 active（语义上） |
| `version` | INTEGER | NOT NULL, DEFAULT 1 | 链内的版本序号 |
| `chain_root_id` | TEXT | NOT NULL, FK brain_skills(skill_id) | 冗余链根 ID（同链上所有节点冗余存储，避免每次 resolve 反查；新建时 = skill_id 自己，supersede 时继承父节点的 chain_root_id） |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 当前版本的入库时刻（FR-029b "最近变更时间" = 当前 active 版本的此字段） |
| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 行最近被写时刻（含状态切换） |
| `last_changed_by` | TEXT | | 当前版本的操作者（assistant / specialist:{id} / user） |
| `change_reason` | TEXT | | 当前版本的变更原因（用户填或 assistant 自填） |
| `loaded_count` | INTEGER | DEFAULT 0 | 被加载次数（FR-041 项 1，沿 supersede 链继承） |
| `referenced_count` | INTEGER | DEFAULT 0 | 被引用执行次数（FR-041 项 3，沿 supersede 链继承） |
| `last_referenced_at` | DATETIME | | 最近一次被引用执行时间（FR-041 / FR-029a 筛选用） |

**状态机**:
```
[creation] → active → (superseded | soft_deleted)
                       ↑
                       supersede 接力：旧 → superseded，新插入为 active
                       soft_delete：active → soft_deleted（高危确认后单事务裁剪装备关系）
```
- `superseded` 与 `soft_deleted` 为终态可观测的历史/失效形态——不再恢复 active，但物理记录保留（FR-008）。
- 物理 DELETE 三层（API / Repository / 直连 SQL）守卫测试阻断（SC-008）。

**索引**:
- `(status)`（active 列表筛选）
- `(name) WHERE status = 'active'`（同名 active 检查，UNIQUE PARTIAL INDEX 实现 FR-024a 唯一硬约束）
- `(chain_root_id)`（链根查询）
- `(parent_skill_id)`（链遍历）
- `(origin)`（按 origin 筛选 + 链根 origin 判定缓存）
- `(last_referenced_at)`（FR-029a "最近 30 天没被引用过" 筛选用）

**字段约束**（在 Repository 层 + CHECK 约束 + 业务层校验三层把守）:
- `name` 非空，最长 200 字（UI/工具入口校验，DB 不限）
- `description` 非空，最长 500 字
- `trigger_conditions` JSON parse 后 ≥ 1 条非空 string（业务层校验 + FR-024b）
- `required_tools` JSON parse 后允许 0 条
- `body_markdown` 非空
- **`name` 在 `status = 'active'` 集合内全库唯一**（UNIQUE PARTIAL INDEX 实现）

### 2. `brain_skill_source_segments`

方法论的素材来源（N:M：一条方法论可引用多条 segment，一条 segment 可被多条方法论引用）。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTOINCREMENT | |
| `skill_id` | TEXT | NOT NULL, FK brain_skills | |
| `segment_id` | TEXT | NOT NULL, FK brain_segments | |
| `source_zone` | TEXT | NOT NULL, CHECK (`source_zone` IN ('archive', 'failure')) | FR-024 限制：仅 archive 或 failure 分区的 segment 可作素材 |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | |

**索引**:
- `(skill_id)`
- UNIQUE `(skill_id, segment_id)`（一条素材只能挂一次到一条方法论）

**约束**:
- 业务层 `SkillService.create_or_supersede` 在写入前校验 segment 当前归属 zone（通过 `BrainRepository.get_segment_zone(segment_id)` 查 `brain_memory_entries.zone` 对应 segment 蒸馏出的条目）必须是 `archive` 或 `failure`，否则拒绝（FR-024 / SC-010）
- `≥ 1` 条素材必填——写入路径校验 `len(source_segments) >= 1`，否则拒绝（FR-024 / SC-010）

### 3. `brain_skill_equipment`

装备者-Skill N:M 装备关系，附带状态机留行能力（FR-014b / SC-026）。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTOINCREMENT | |
| `equipped_entity_type` | TEXT | NOT NULL, CHECK (`equipped_entity_type` IN ('assistant', 'specialist')) | 装备者类型（assistant 本体 / specialist） |
| `equipped_entity_id` | TEXT | NOT NULL | 装备者 ID：assistant 类型固定为字面量 `'_assistant'`；specialist 类型为 `brain_specialists.specialist_id` |
| `skill_id` | TEXT | NOT NULL, FK brain_skills | 装备的方法论（指向 active 版本；supersede 时切换） |
| `status` | TEXT | NOT NULL, DEFAULT `active`, CHECK (`status` IN ('active', 'unequipped')) | 装备关系状态机封闭枚举 |
| `equipped_order` | INTEGER | NOT NULL, DEFAULT 0 | 装备顺序（系统 prompt 注入顺序；用户在 UI 调整） |
| `equipped_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | |
| `unequipped_at` | DATETIME | | 卸下时间（status = 'unequipped' 时填充） |
| `unequipped_reason` | TEXT | CHECK (`unequipped_reason` IN ('user_unequip', 'force_remove_on_soft_delete', 'supersede_transfer', NULL)) | 卸下来源标签封闭枚举（与 `origin` 枚举语义独立） |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 行入库时刻 |

**状态机**:
```
[creation] → active → unequipped
卸下 = 标 unequipped + 填 unequipped_at + 填 unequipped_reason；不删行。
再装备 = 新建一行 status='active'（不复用历史 unequipped 行）；旧 unequipped 行保留作审计。
supersede 切版本 = 同事务内，旧 skill_id 的 active 行 → unequipped（reason='supersede_transfer'），同时为新 skill_id 插入对应 active 行。
强制软删除自动裁剪 = 标 unequipped + reason='force_remove_on_soft_delete'，单事务内与 skill 行 status 切换同步。
```

**索引**:
- UNIQUE PARTIAL INDEX `(equipped_entity_type, equipped_entity_id, skill_id) WHERE status = 'active'` —— 每对 (装备者, skill) 至多 1 行 active 装备关系（FR-014b 数据库层约束）
- `(equipped_entity_type, equipped_entity_id, status)`（按装备者列出当前装备清单）
- `(skill_id, status)`（按方法论列出当前装备者；FR-040 计数 + 受影响装备者查询）
- `(equipped_entity_type, equipped_entity_id, equipped_order)`（按顺序列出装备清单）

**物理 DELETE 阻断**:
- Repository 不暴露 `delete_*` 方法
- API 路由不接受 DELETE 物理删除请求（DELETE HTTP 方法在 API 路由 mapping 到 "标 unequipped" 而非真删）
- 守卫测试 `test_skill_no_physical_delete.py` 阻断三路径（API / Repository / 直连 SQL）

## 关键关系图

```
brain_skills (方法论资产)
    ├── parent_skill_id → brain_skills (supersede 链反向指针)
    ├── superseded_by → brain_skills (supersede 链正向指针，可空，仅 status='superseded' 时填)
    ├── chain_root_id → brain_skills (冗余链根 ID)
    ├── 1:N → brain_skill_source_segments (素材来源)
    │            └── segment_id → brain_segments
    └── 1:N → brain_skill_equipment (装备关系)
                 └── equipped_entity (assistant | specialist) → brain_specialists / 字面量 '_assistant'
```

## 状态机汇总

### Skill 状态机（FR-008）
- `active`（创建即此态）
- `active → superseded`（被 supersede 接力时；旧版本切此态、新版本入库为 active）
- `active → soft_deleted`（用户软删除时；走 FR-020 高危同步确认 + 装备关系裁剪单事务）
- `superseded` 与 `soft_deleted` 为终态可观测形态，不可恢复
- **不引入 `draft` / `rejected` 中间态**（FR-008）

### Equipment 状态机（FR-014b）
- `active`（装备即此态）
- `active → unequipped`（用户卸下 / 强制裁剪 / supersede 切版本）
- 同对 (装备者, skill) 再次装备 = 新建一行 active，历史行保留

## 数据回填（Migration v12 Bootstrap 步骤）

Migration v12 在创建完上述三张表 + 索引后，由 data 层迁移函数自包含插入 bootstrap 数据，不反向 import business service：

1. 读取随包发布的默认 seed 文件
   - 文件读取成功 → 用真实 seed body
   - 文件缺失 / 空 / IO 异常 / 编码错误 → 用 data-owned fallback 常量
2. INSERT 一行 `brain_skills`:
   - `skill_id` = 新 UUID
   - `name` = "如何创建方法论"
   - `description` = "调用 create_skill_methodology 工具时的参数填写指引与判重义务"
   - `trigger_conditions` = `["assistant 准备调用 create_skill_methodology 工具产出新方法论时", "受授权 specialist 准备调用 create_skill_methodology 工具时"]`
   - `required_tools` = `["create_skill_methodology"]`
   - `body_markdown` = seed body 或 fallback body
   - `status` = `active`
   - `origin` = `system_bootstrap`
   - `parent_skill_id` = NULL（链根）
   - `chain_root_id` = 自身 skill_id
   - `version` = 1
3. INSERT 一行 `brain_skill_equipment`:
   - `equipped_entity_type` = `assistant`
   - `equipped_entity_id` = `_assistant`
   - `skill_id` = 上一步的 skill_id
   - `status` = `active`
   - `equipped_order` = 0
   - **不**对当时已有的 specialist 追加装备（FR-014a 例外）
4. migration 不发 UI 事件；应用启动后的 `SkillBootstrapService.ensure_bootstrap_skill()` 与 `GET /api/skills/methodology/bootstrap-status` 负责检测 fallback，前端展示 toast

应用启动时调用 `SkillBootstrapService.ensure_bootstrap_skill()`（详见 D9）做自愈：
- 链上无 `user_edit` 接力 且当前 active 是 fallback body → 用真实 seed 自动 supersede
- 链上已有 `user_edit` → 不自动覆盖，尊重用户
