# Events Contract: Skill Methodology Layer

Generated by `/speckit-plan` — Phase 1 output.

## 概览

事件分两层：
- **后端 blinker 事件**（在 `src/utils/events.py` 集中定义）：后端跨模块通知
- **前端 UI Event Registry**（在 `src/desktop_api/ui_events.py` 注册）：面向前端的 typed envelope

两层一对一映射，desktop_api adapter 在监听 blinker 事件后转换为 UI Event 推到前端 event stream。

---

## 1. 后端 blinker 事件（新增）

定义位置：`src/utils/events.py`

### 1.1 `brain_skill_changed`
- **Sender 语义**: skill_id（字符串）
- **Payload kwargs**:
  - `operation`: `create` | `supersede` | `user_edit` | `soft_delete`
  - `chain_root_id`: str
  - `new_skill_id`: str（supersede / user_edit 路径下的新版本 id；create 路径下 = sender）
  - `caller_type`: `assistant` | `specialist` | `user` | `system`
  - `caller_id`: str（specialist id / `_assistant` / `_user` / `_system`）
- **Emit 位置**: `SkillService.create` / `SkillService.supersede` / `SkillService.user_edit` / `SkillService.soft_delete` 路径末尾，事务提交后

### 1.2 `brain_skill_equipment_changed`
- **Sender 语义**: skill_id 或 entity_id（取决于变更视角）
- **Payload kwargs**:
  - `change_type`: `equipped` | `unequipped` | `reorder` | `supersede_transfer` | `force_remove_on_soft_delete` | `default_propagate`
  - `entity_type`: `assistant` | `specialist`
  - `entity_id`: str
  - `skill_id`: str
  - `unequipped_reason`: str | None
- **Emit 位置**: `SkillEquipmentService` 各路径事务提交后

### 1.3 `brain_skill_supersede_completed`
- 用于审计与版本链刷新通知
- **Sender 语义**: chain_root_id
- **Payload kwargs**:
  - `old_skill_id`: str
  - `new_skill_id`: str
  - `version`: int
  - `equipment_count_migrated`: int
- **Emit 位置**: `SkillService.supersede` 事务提交后（与 `brain_skill_changed` 并发 emit）

### 1.4 `brain_skill_bootstrap_fallback_used`
- **Sender 语义**: skill_id（bootstrap 写入的 fallback skill_id）
- **Payload kwargs**:
  - `reason`: `seed_file_missing` | `seed_file_empty` | `seed_file_io_error`
  - `seed_file_path`: str
- **Emit 位置**: `SkillBootstrapService.bootstrap_missing_skill` 或 `ensure_bootstrap_skill` 路径

## 2. UI Event Registry（新增）

定义位置：`src/desktop_api/ui_events.py` UI_EVENT_REGISTRY

### 2.1 `skill.changed`（新增）
```python
"skill.changed": UiEventDefinition(
    "skill.changed",
    "notification",
    payload_keys=frozenset({
        "reason",        # 'create' | 'supersede' | 'user_edit' | 'soft_delete' | 'bootstrap_fallback_used'
        "skillId",
        "chainRootId",
        "newSkillId",
        "callerType",
        "callerId",
        "bootstrapFallbackUsed",  # bool, optional; only true when reason == 'bootstrap_fallback_used'
        "bootstrapFallbackInfo"   # {"reason": "...", "seedFilePath": "..."}, optional
    }),
    scope_keys=frozenset({"skillId"}),
    example={"reason": "create", "skillId": "skl_abc", "chainRootId": "skl_abc"},
    required_payload_keys=frozenset({"reason", "skillId", "chainRootId"}),
    required_scope_keys=frozenset({"skillId"}),
    payload_enum_values=(
        ("reason", frozenset({"create", "supersede", "user_edit", "soft_delete", "bootstrap_fallback_used"})),
        ("callerType", frozenset({"assistant", "specialist", "user", "system"})),
    ),
)
```

**重要约束（CC-004）**:
- payload 不含 `body_markdown` / 完整正文 / `trigger_conditions` 全文等大字段
- 前端按 `skillId` 走 `GET /api/skills/methodology/{id}` 拉详情

### 2.2 `skill.equipment.changed`（新增）
```python
"skill.equipment.changed": UiEventDefinition(
    "skill.equipment.changed",
    "notification",
    payload_keys=frozenset({
        "changeType",          # 'equipped' | 'unequipped' | 'reorder' | 'supersede_transfer' | 'force_remove_on_soft_delete' | 'default_propagate'
        "entityType",          # 'assistant' | 'specialist'
        "entityId",
        "skillId",
        "unequippedReason"     # str | null
    }),
    scope_keys=frozenset({"entityId", "skillId"}),
    example={"changeType": "equipped", "entityType": "assistant", "entityId": "_assistant", "skillId": "skl_abc"},
    required_payload_keys=frozenset({"changeType", "entityType", "entityId", "skillId"}),
    payload_enum_values=(
        ("changeType", frozenset({
            "equipped", "unequipped", "reorder",
            "supersede_transfer", "force_remove_on_soft_delete", "default_propagate"
        })),
        ("entityType", frozenset({"assistant", "specialist"})),
    ),
)
```

### 2.3 既有 `skills.changed` → `tools.changed`（改名，无双发）
原 `skills.changed` 定义整体替换为 `tools.changed`，payload_keys 与 example 不变：

```python
"tools.changed": UiEventDefinition(
    "tools.changed",
    "notification",
    payload_keys=frozenset({"reason", "toolId", "status"}),
    scope_keys=frozenset({"toolId"}),
    example={"reason": "catalog_invalidated"},
)
```

- `events.py` 内 `skills_changed` blinker signal 改名为 `tools_changed`
- 所有 emit 调用点同步切换
- UI Event Registry 不再注册 `skills.changed`——一次性下线（CC-006 / FR-003 / SC-012）

### 2.4 `assistant.confirmation`（既有，扩展 actionType 枚举）
sk-protected edit 与 sk-soft-delete 复用现有 assistant.confirmation 浮层（与 FR-027a / FR-020 同协议）：

新 actionType 枚举值：
- `skill.edit_protected` —— FR-027a 编辑保护链根 origin 为 system_bootstrap 的方法论时触发；payload 含 `affectedSkillId`
- `skill.soft_delete` —— FR-020 软删除有装备者的方法论时触发；payload 含 `affectedSkillId`、`affectedEquipmentCount`、`affectedSpecialistNames: [str]`

这些 actionType 走 UI_EVENT_REGISTRY 的 `assistant.confirmation` 既有 `payload_enum_values` 扩展，**不**新增独立事件 type。前端 confirmation 浮层组件按 actionType 渲染不同文案。

### 2.5 `backend.resync_required` payload 扩展
既有事件，扩展 `domains` 枚举值，新增 `"skill"` 域：
```python
example={"reason": "replay_gap", "domains": ["teaching", "skills", "brain", "skill"]}
```

前端在重连缺口时按 `domains` 列表拉权威快照——`"skill"` 域刷新方法论列表 + 装备关系 + bootstrap status。

## 3. Event Stream Consumption（前端）

`frontend/src/state/skillMethodologyStore.ts`（新增）订阅：
- `skill.changed` → 触发对应 store action（list 失效 + detail 刷新）
- `skill.equipment.changed` → 触发 specialistStore + skillMethodologyStore 双向刷新
- `tools.changed` → 复用既有 skillsStore（Tool 域）逻辑，名称变了但行为同
- `backend.resync_required` with `domains` 含 `"skill"` → 调 `/api/skills/methodology` 拉权威快照
