# Agent Tools Contract: Skill Methodology Layer

Generated by `/speckit-plan` — Phase 1 output.

## 概览

本 feature 引入两个 agent 工具，与 010 现有工具协议同模式（schema in `assistant_tools.py` style；handler factory 绑定 session_id / agent context）。

---

## Tool 1: `create_skill_methodology`

**用途**: 装备者（assistant 调度层本体 / 受授权 specialist）把对话中刚发生的工作流程提炼成 active 方法论入库。

**默认装备**: 仅 assistant 调度层本体的工具白名单内包含此工具。用户可在 SpecialistScreen 主动授权给个别 specialist（与既有 `tool_whitelist` 机制一致）。

**Schema**:
```json
{
  "name": "create_skill_methodology",
  "description": "把一段已发生的工作流程提炼为可被装备的方法论资产。新建模式产出全新方法论；supersede 模式产出已有方法论的新版本。",
  "input_schema": {
    "type": "object",
    "properties": {
      "mode": {
        "type": "string",
        "enum": ["create", "supersede"],
        "description": "create=新建；supersede=对已有方法论接力新版本"
      },
      "target_skill_id": {
        "type": "string",
        "description": "supersede 模式必填，要 supersede 的当前 active 方法论 id；create 模式不传"
      },
      "name": {"type": "string", "description": "方法论名称（人类可读，建议 ≤ 30 字）"},
      "description": {"type": "string", "description": "一句话短描述（≤ 100 字）"},
      "trigger_conditions": {
        "type": "array",
        "items": {"type": "string"},
        "description": "触发条件 list（必须 ≥ 1 条非空），每条是装备者自己读的自然语言短句"
      },
      "required_tools": {
        "type": "array",
        "items": {"type": "string"},
        "description": "本方法论执行时建议或需要的工具名 list；允许 0 条"
      },
      "body_markdown": {"type": "string", "description": "方法论正文 Markdown，描述完整步骤"},
      "source_segments": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "segment_id": {"type": "string"},
            "source_zone": {"type": "string", "enum": ["archive", "failure"]}
          },
          "required": ["segment_id", "source_zone"]
        },
        "description": "素材来源 list（必须 ≥ 1 条），每条标注 zone（仅允许 archive / failure）"
      },
      "change_reason": {"type": "string", "description": "本次产出的原因（自动产物强制非空）"}
    },
    "required": ["mode", "name", "description", "trigger_conditions", "body_markdown", "source_segments", "change_reason"]
  }
}
```

**Handler Behavior**:
1. 校验阶段：
   - `mode = 'supersede'` 时必填 `target_skill_id`，否则拒绝（`missing_target_skill_id`）
   - `trigger_conditions` 非空 list 且 ≥1 条非空 string（剥离纯空白）→ 否则拒绝（`skill_trigger_conditions_required`，对应 SC-022）
   - `source_segments` ≥1 条且每条的 `source_zone` ∈ `{archive, failure}` → 否则拒绝（`skill_source_segments_required` / `skill_source_segment_wrong_zone`，对应 SC-010）
   - 业务层调 `BrainRepository.get_segment_zone(segment_id)` 校验 segment 当前 zone 与传入 `source_zone` 一致 → 否则拒绝
2. 鉴权阶段：调用方（assistant / specialist）的工具白名单必须含 `create_skill_methodology` → 否则工具层鉴权拒绝（`unauthorized_tool_call`，对应 SC-009）
3. 模式分支：
   - `mode = 'create'`: 校验全库无同名 active（FR-024a）→ INSERT 新 skill 行（status='active', origin = `assistant_tool_call` 或 `specialist_tool_call`，依据 caller agent type；parent_skill_id=NULL；chain_root_id=自身），并触发 FR-014a 默认全装备传播（除 `system_bootstrap` 例外，此处不触发该例外因 origin 不是 system_bootstrap）
   - `mode = 'supersede'`: 走 D10 BEGIN IMMEDIATE 事务：读 target 当前 active 链根 + 当前 active → 旧 → superseded → 新 INSERT → 装备关系切换 → 计数继承
4. Return 结构化 result（assistant agent 用以确认入库成功）：
```json
{
  "success": true,
  "skill_id": "skl_new",
  "chain_root_id": "skl_root",
  "version": 2,
  "name": "...",
  "auto_equipped_to": ["_assistant", "spec_a", "spec_b"]
}
```
失败 result:
```json
{
  "success": false,
  "error": "skill_name_collision",
  "message": "全库已存在同名 active 方法论",
  "occupied_skill_id": "skl_other"
}
```

**事件副作用**:
- 成功后 emit blinker `brain_skill_changed`（sender=skill_id, operation='create' or 'supersede'）
- emit blinker `brain_skill_equipment_changed`（如果触发了装备关系切换/传播）
- desktop_api adapter 把 blinker 事件转换为 UI Event Registry `skill.changed` / `skill.equipment.changed` 推到前端

## Tool 2: `load_skill_methodology`

**用途**: 装备者按需拉取自己已装备的方法论完整正文。

**默认装备**: 所有装备者（specialist + assistant 本体）自动装备此工具，不需要单独授权。

**Schema**:
```json
{
  "name": "load_skill_methodology",
  "description": "拉取你已装备的某条方法论的完整正文（SKILL.md 形态）。先看 system prompt 里的装备清单条目（id / 名称 / 描述 / 触发条件），按 trigger_conditions 判断本轮场景是否真命中再 load 该方法论；不应单轮无差别 load 整个装备清单。",
  "input_schema": {
    "type": "object",
    "properties": {
      "skill_id": {"type": "string", "description": "要 load 的方法论 id，必须在你当前装备清单内"}
    },
    "required": ["skill_id"]
  }
}
```

**Handler Behavior**:
1. 校验 caller 当前装备清单包含 `skill_id` 对应的 active 装备关系（按 `equipped_entity_type` + `equipped_entity_id` 查 `brain_skill_equipment` WHERE skill_id=<input> AND status='active'）；不在则拒绝（`skill_not_in_equipment`）
2. 校验 skill 行当前 `status = 'active'`；如果已 superseded / soft_deleted → 拒绝（`skill_not_active`）
3. 渲染 SKILL.md 形态文本（详见 research.md D5）
4. 调用 `SkillReferenceCounterService.increment_loaded_count(skill_id)` → 本轮 +1
5. **无单轮调用次数硬上限**（FR-017b / SC-024）——同一 caller 在单轮 reply 内反复调同一或不同 skill_id 均接受

**Return**: SKILL.md 文本字符串（直接作为 tool result message content）

## reply_to_user Schema 扩展（既有工具增强，不新增工具）

assistant_tools.py 内 `REPLY_TO_USER_SCHEMA` 增加 `skills_referenced` 字段，与既有 `memory_entries_referenced` 并列：

```json
{
  "memory_entries_referenced": {
    "type": "array",
    "items": {"type": "string"},
    "description": "本条回复引用的记忆条目 ID 列表"
  },
  "skills_referenced": {
    "type": "array",
    "items": {"type": "string"},
    "description": "本条回复真按方法论步骤走了的 skill_id list；与装备清单或加载行为无关，仅在装备者认为'我这一轮真按它走了'时列出。系统在落库时按 supersede 链根归一化 +1。"
  }
}
```

**Handler 行为变化**:
- `reply_to_user` handler 在原有 `batch_update_referenced_counts(memory_entries_referenced)` 调用之外，追加一次 `SkillReferenceCounterService.batch_increment_referenced(skills_referenced)` 调用
- 字段缺失或格式错误 → 静默跳过本轮（与 `memory_entries_referenced` 同模式；FR-041 / SC-016d）

## 工具被装备的位置

- `create_skill_methodology`:
  - assistant 调度层 system prompt 工具白名单：默认装备
  - assistant 调度层本体的方法论装备清单：默认包含"如何创建方法论"内置方法论（指引正文）
  - specialist 工具白名单：默认不装备（FR-025 / SC-009）；用户可在 SpecialistScreen 主动授权
- `load_skill_methodology`:
  - 装备给所有装备者，作为框架级工具（不需要在 `tool_whitelist` 内显式列出，工具层默认放行；与既有"框架基础工具"模式一致）
